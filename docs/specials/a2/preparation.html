每一行在做什么 / Read every line · 5 行

行号与上方代码一致。先读这一行改变了什么，再把它放回整条查询；括号、别名和注释也有说明。

  1. 01BEGIN;

    原题用银行例子说明 SQL BEGIN：它开启一个会话事务，与触发器函数内部的 BEGIN 不同。

    The original banking example uses SQL BEGIN to open a transaction, unlike BEGIN inside a trigger function.

  2. 02UPDATE accounts SET balance = balance - 100.00

    对符合下一行 WHERE 的账户把 balance 减去 100.00。UPDATE 中的新值依赖该行现有 balance，不是直接改成 100。

    Subtract 100.00 from the matching row’s existing balance rather than replacing the balance with 100.

  3. 03 WHERE name = 'Alice';

    限定 name 为 Alice；单引号是字符串。这个示例表不属于 FleetDB，不能直接在 assignment2 中假定 accounts 存在。

    Restrict the example to Alice. accounts is an illustrative table, not one of FleetDB’s tables.

  4. 04-- some more statements etc etc

    注释表示同一个事务里还可以有其他语句，本行本身不会执行。

    The comment indicates more statements could belong to the same transaction; it performs no action.

  5. 05COMMIT;

    事务未失败时 COMMIT 提交其全部改动；不是每条 UPDATE 都单独确认。若事务已异常失败，则需要按失败状态理解最终结果。

    COMMIT saves all changes of a healthy transaction together; the outcome differs if the transaction has already failed.

原题对普通读取“不拿锁”的说法是教学简化：PostgreSQL 普通 SELECT 仍会取得兼容的 ACCESS SHARE 表锁，但不会因此锁住车辆的可用状态或预留车辆。函数里的 BEGIN 也不会新开一笔事务。

The original no-lock statement is a teaching simplification: an ordinary SELECT still takes a compatible ACCESS SHARE relation lock, without reserving vehicle availability. BEGIN inside the function does not start an independent transaction.

CREATE OR REPLACE FUNCTION UDF_BI_COLLECT() RETURNS TRIGGER AS $$
DECLARE
    last_type   VARCHAR;
    last_member INTEGER;
BEGIN
    IF NEW.event_type = 'Collect' THEN

        SELECT E.event_type, E.member_id
          INTO last_type, last_member
          FROM BOOKING_EVENTS E
         WHERE E.vehicle_id = NEW.vehicle_id
         ORDER BY E.event_time DESC, E.event_id DESC
         LIMIT 1;

        IF last_type = 'Incident' THEN
            RAISE EXCEPTION
                'Vehicle % is off the road pending repair', NEW.vehicle_id;
        ELSIF last_type = 'Collect' THEN
            RAISE EXCEPTION
                'Vehicle % is already out on hire', NEW.vehicle_id;
        ELSIF last_type = 'Reserve' AND last_member <> NEW.member_id THEN
            RAISE EXCEPTION
                'Vehicle % is reserved by member %', NEW.vehicle_id, last_member;
        END IF;

    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
