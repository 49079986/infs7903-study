Q3.1.1

TASK SUMMARY + LINE GUIDE
中文题意 / Task in Chinese

（1.5分）分别用NOT EXISTS与不含NOT EXISTS/NOT IN的方法列从未Collect车辆，两者结果相同。

(1.5 marks) List never-Collected vehicle ids with NOT EXISTS and without NOT EXISTS/NOT IN, returning identical rows.

解答、逐行代码与实测依据 / Solution, line guide and evidence

NOT EXISTS 与 LEFT JOIN 后保留 e.vehicle_id IS NULL 都返回相同的 75 辆车。外连接中的 Collect 条件必须放在 ON 中；若放入 WHERE，会错误丢掉没有匹配的车辆。

Both statements return the same 75 vehicle IDs, ordered by vehicle_id. Statement A uses a correlated NOT EXISTS test. Statement B places the Collect predicate in the LEFT JOIN condition and keeps rows with no matching event vehicle_id. The matched-side vehicle_id is NOT NULL in the schema, so NULL identifies an unmatched vehicle unambiguously.

匹配侧的 vehicle_id 在 schema 中非空，因此 NULL 能可靠表示没有匹配。独立的双向 EXCEPT ALL 检查未发现差异；这不是依靠肉眼比较前几行得出的结论。

Putting event_type in WHERE instead of ON would remove the unmatched rows and break the outer-join solution. Independent EXCEPT ALL checks in both directions found no differences. The screenshots show the first ten and last ten rows of each 75-row result.

A2_3.1.1.sql
-- INFS7903 Assignment 2 | Public teaching edition
-- Statement A
SELECT v.vehicle_id
FROM VEHICLES v
WHERE NOT EXISTS (
    SELECT 1 FROM BOOKING_EVENTS e
    WHERE e.vehicle_id = v.vehicle_id
      AND e.event_type = 'Collect'
)
ORDER BY v.vehicle_id;
-- Statement B
SELECT v.vehicle_id
FROM VEHICLES v
LEFT JOIN BOOKING_EVENTS e
  ON e.vehicle_id = v.vehicle_id
 AND e.event_type = 'Collect'
WHERE e.vehicle_id IS NULL
ORDER BY v.vehicle_id;

Q3.1.2

TASK SUMMARY + LINE GUIDE
中文题意 / Task in Chinese

（1.5分）比较两个查询计划，解释反连接改写。

(1.5 marks) Compare both execution plans and explain any anti-join transformation.

解答、逐行代码与实测依据 / Solution, line guide and evidence

两种写法得到相同的 Hash Right Anti Join 和最终排序，cost 都为 4579.18..4579.30；估计 48 行，实际 75 行。执行时间分别为 12.788 和 12.558 ms。

The two plans have the same operator structure and cost 4579.18..4579.30. Both return 75 rows, versus 48 estimated, using Hash Right Anti Join and a final vehicle_id sort. Statement A takes 12.788 ms and Statement B 12.558 ms in these runs.

优化器把 NOT EXISTS 去相关，并识别外连接的 NULL 检查为相同 anti-join。它对 900 辆车建 hash，经 bitmap 路径处理 59,539 条 Collect。Right 表示物理输入方向，不改变“保留从未取车的车辆”语义；不是为每辆车重扫整张日志。

PostgreSQL decorrelates NOT EXISTS and recognizes the outer-join NULL filter as the same anti-join operation. It hashes the small set of 900 vehicles and scans 59,539 Collect events through a bitmap index/heap path, keeping the vehicle rows without any match. The Right direction describes the physical join inputs chosen by the optimizer; it preserves the intended vehicle-side anti-join semantics. Neither syntax forces a separate full event scan for each vehicle. The minor time difference does not establish a consistent performance difference.

LEFT JOIN BOOKING_EVENTS e
  ON e.vehicle_id = v.vehicle_id
 AND e.event_type = 'Collect'
WHERE e.vehicle_id IS NULL
ORDER BY v.vehicle_id;
