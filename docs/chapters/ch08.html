INFS7903 · CH08

查询处理与成本模型Query processing and cost models

学习目标：逻辑操作怎样执行Learning objectives: implementing logical operators

来源 / Source: Lecture/Week08-QPO-01(1).pdf · PDF p. 3-12（原资料留在本地版） · 本地逐页图文 / Local pages

目标是解释SQL从解析到执行的路径，比较选择、投影与连接的实现，估计中间结果大小并计算给定成本模型。前置是第5–7章的块、索引和RA。查询执行计划（query execution plan，QEP）把逻辑需求组织成可执行操作树；叶是访问基表，父节点消费孩子输出，通常从下向上理解。

The goal is to explain parsing through execution, compare implementations of selection, projection and join, estimate intermediate sizes and calculate a stated cost model. Prerequisites are blocks, indexes and RA from Chapters 5–7. A query execution plan (QEP) organises logical requirements into executable operations. Leaves access base relations and parents consume child output, so read the tree from the bottom upwards.

解析器检查SQL语法与名称，语义分析连接目录中的列、类型和权限；重写展开视图；规划器选择顺序、访问路径与连接算法；执行器产生结果。目录中的行数、键、外键、索引和分布估计影响规划。逻辑等价不等于代价相同：同样答案可先过滤或先连接、走索引或全扫。

The parser checks syntax and names, semantic analysis resolves columns, types and privileges through the catalogue, rewriting expands views, the planner chooses ordering, access paths and join methods, and the executor produces results. Row counts, keys, foreign keys, indexes and distribution estimates affect planning. Logically equivalent plans need not have equal cost: they can filter before joining, join first, use an index or scan.

选择与投影的实现条件Implementing selection and projection

来源 / Source: Lecture/Week08-QPO-01(1).pdf · PDF p. 11-13（原资料留在本地版） · 本地逐页图文 / Local pages

没有合适访问路径时，选择需检查全表；按有序键可二分定位，索引可直接找候选位置，哈希适合等值。多条件AND可以先用一个强过滤索引再检查其他条件，也可组合索引或交集记录位置。OR常需把各分支结果并起来并处理重复，不能用AND式串联筛选替代。

Without a suitable access path, selection examines the table. Ordered keys permit binary positioning, indexes identify candidate locations and hashing suits equality. Conjunctive predicates can use one restrictive index followed by residual checks, a composite index or intersection of record locations. Disjunction often combines branch results with duplicate handling; it cannot be implemented as successive AND filters.

经典投影需要去重，可排序后线性扫描相邻值，也可哈希去重。课程采用排序模型P(N)=N(1+log N)：N log N为排序，N为扫描。若已排序，或数据库仅取列而不DISTINCT，费用不同。投影还减少每行宽度，即使行数不变也可能节省内存、临时文件和传输。

Classical projection removes duplicates, using sorting followed by adjacent-value elimination or hash-based deduplication. The course uses P(N)=N(1+log N): N log N for sorting and N for scanning. Already sorted input or SQL column selection without DISTINCT has different cost. Projection also narrows rows, saving memory, temporary storage and transfer even when cardinality stays unchanged.

三种连接算法与逐步示例Three join methods and a stepwise example

来源 / Source: Lecture/Week08-QPO-01(1).pdf · PDF p. 14-23（原资料留在本地版） · 本地逐页图文 / Local pages

嵌套循环连接（nested-loop join）对R每行遍历S，朴素比较次数约N×M，适用于任意连接谓词，但大输入很贵。块式嵌套循环一次把若干外表页留内存再扫描内表，减少重复I/O。教学补充：若内存有K页，可用近似I/O bR+⌈bR/(K−2)⌉bS，预留内表与输出缓冲；这是另一单位的模型，不能与课件元组成本直接相加。

A nested-loop join scans S for each row of R, making roughly N×M comparisons in its simplest form. It supports arbitrary predicates but is costly for large inputs. Block nested loops retain several outer pages before scanning the inner input, reducing repeated I/O. Teaching supplement: with K buffer pages, approximate I/O by b R+⌈b R/(K−2)⌉b S, reserving inner and output buffers. This page-cost model has different units from the lecture’s tuple model and must not be added directly to it.

课程单循环连接（single-loop join）实际使用内表连接字段索引：对每个外表键probe一次内表。成本约为扫描外表+外表行数×每次索引查找与结果读取。外表较小常有利，但内表有无索引、键重复和匹配行是否聚簇同样重要。“只用一个循环”并不说明内部查找免费。

The course’s single-loop join probes an inner index on the join field for each outer key. Its cost is approximately the outer scan plus outer row count times indexed lookup and result fetching. A small outer input often helps, but inner indexing, duplicate keys and clustering also matter. One explicit loop does not make the inner search free.

排序合并连接（sort-merge join）先按连接键排序，比较当前键：左小则推进左，右小推进右，相等则输出匹配。输入已排序时合并近似线性。课程无重复例子R=[1,3,4,5]、S=[2,3,5,6]，依次跳过1、2，输出3，再跳4，输出5，结束。对重复键必须输出整组笛卡尔配对，例如两边各两个3要输出4行。

A sort-merge join first sorts both join keys, then advances the side with the smaller current key and emits matching pairs on equality. Already sorted inputs merge approximately linearly. In the course’s unique-key example R=[1,3,4,5], S=[2,3,5,6], skip 1 and 2, emit 3, skip 4 and emit 5. Duplicate groups require every pairing: two rows with key 3 on each side produce four joined rows.

教学补充：哈希连接（hash join）按等值键建立较小输入的哈希表，再扫描较大输入probe。若内存不足可分区并写临时文件，因此不是所有场景都一次线性完成。非等值条件如E.deptno>D.deptno一般不能只靠普通等值哈希直接实现，Prac6因此展示嵌套循环。物理算法选择依赖连接条件和可用排序、索引与内存。

Teaching supplement: a hash join builds a hash table on the smaller equality-key input and probes it while scanning the larger input. Insufficient memory can require partitioning and temporary writes, so it is not always one linear pass. A non-equality predicate such as E.deptno>D.deptno cannot generally use an ordinary equality hash join directly, explaining Prac 6’s nested loop. Method selection depends on predicates and available order, indexes and memory.

模式约束决定结果基数Schema constraints determine cardinality

来源 / Source: tut/Tut08-QP-2026.pdf · PDF p. 1-5（原资料留在本地版） · 本地逐页图文 / Local pages

关系基数（cardinality）|R|是行数，属性的NDV是不同值数，两者要分开。选择行数在0与|R|之间；πA后的不同值数至多min(|R|,NDV(A))；乘积是|R||S|。若子表外键非空并引用唯一存在父键，子表⋈父表恰好每个子行配一个父行，结果等于子表行数。外键可空或父表先被过滤时则不能保证。

Relation cardinality |R| is a row count, whereas an attribute’s NDV counts distinct values. Selection yields between zero and |R| rows; projection onto A yields at most min (|R|, NDV(A)); a product yields |R||S|. If a non-null child foreign key references an existing unique parent key, each child joins exactly once and the result equals the child count. Nullable references or a filtered parent invalidate that guarantee.

Tutorial 8 Ex3只让依据模式与基数求界：11行Course_Taken筛Spring12，范围0–11，不能偷用给出的实际值算7。Course_Taken按非空有效Course_No外键连接Course，行数恰好11，列数4+3−1=6。把“选择后的确切数”“统计估计”“结构上保证的上下界”分开，是这题真正考查的能力。

Tutorial 8 Ex 3 asks for bounds based on schemas and counts: selecting Spring 12 from eleven Course_Taken rows gives 0–11, rather than using the actual values to calculate seven. Joining Course through its valid non-null Course_No foreign key gives exactly eleven rows and arity 4+3−1=6. Distinguishing exact evaluation, statistical estimates and structural bounds is the skill being tested.

完整成本比较与课件复算A complete cost comparison and re calculation

本段固定使用课件公式并统一log₂：S(N)=N，P(N)=N(1+log₂N)，J(N,M)=P(N)+P(M)。它们是抽象运算单位，不是毫秒，也没有计算缓存和索引。设Student=25,000、Enrolment=100,000、Course=4,000，5%选课记录Grade=7；课程文字偶写“5%的学生”，这里按筛选Enrolment行解释。

This comparison fixes the lecture formulas with log₂ throughout: S(N)=N, P(N)=N(1+log₂N), and J(N, M)=P(N)+P(M). Units are abstract operations, not milliseconds, and omit caching and indexes. Let Student have 25,000 rows, Enrolment 100,000 and Course 4,000, with 5% of enrolment rows having Grade=7. The slides sometimes say 5% of students; this calculation interprets the filter over Enrolment rows.

比较时必须对两个计划采用同一log底数、去重假设和物理算法。若输入已经排序，不能每个连接又无条件重复收费一次排序；若采用流水线（pipelining），中间结果也不一定全部落盘。课程模型用于练习操作顺序影响，真实DBMS应阅读实际计划。

Compare plans using the same logarithm base, deduplication assumptions and physical algorithms. Already sorted inputs need not be charged for sorting again at every join, and pipe lining can avoid writing entire intermediate results. The course model teaches ordering effects; actual DBMS behaviour requires reading its plan.

总结与自测Summary and self-check

连接的结果行数由匹配语义决定，连接成本由实施方法和输入规模决定，二者不能混为一谈。外键能保证结果不膨胀，却不保证不用索引也只比较子表行数次。先估计各阶段行数与行宽，再按给定算法计算成本。

Join cardinality follows matching semantics; join cost follows implementation and input size. A foreign key can prevent result expansion without ensuring that an un indexed implementation makes only one comparison per child. Estimate row counts and widths at each stage before applying the stated cost model.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

每条左行与每条右行都满足连接条件，共2×2。若只在相等时各推进一次，会只输出两行并遗漏合法配对。正确方法保留并处理整个重复键组。

Each left row matches each right row, giving 2×2 pairs. Advancing both pointers once per equality would emit only two and omit valid matches. Process the full duplicate-key groups.
