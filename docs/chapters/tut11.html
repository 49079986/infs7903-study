两者先读旧X再写，后写覆盖前写，是丢失更新，也可能脏写。T2先完成X并提交，再让T1读最新X。若双方都已拿共享锁再升级，可能死锁，修复序列可让T1在开始X读前等待而非假设升级必成功。

Both read old X before writing, so a later write loses the earlier update and can be a dirty write. Complete T2’s Xwork and commit before T1 reads it. If both first hold shared locks, upgrades can deadlock; the repaired sequence can delay T1’s initial Xread instead of assuming an upgrade succeeds.
