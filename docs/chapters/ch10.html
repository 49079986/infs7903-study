对应 A2 专项：快照与事务交错 / Assignment connection →

学习目标与事务的业务边界Learning objectives and transaction boundaries

来源 / Source: Lecture/Week10-TM(1).pdf · PDF p. 3-24（原资料留在本地版） · 本地逐页图文 / Local pages

目标是解释ACID，追踪交错读写的值，独立构造优先图并判断冲突可串行化，另外检查可恢复、无级联与严格性。前置是SQL修改、基本图论与“事务本地副本”观念。事务（transaction）是一项业务工作对应的逻辑读写单元，例如转账同时扣A、加B；只做一半会破坏业务不变量。

The goal is to explain ACID, trace values under interleaving, construct precedence graphs and test conflict serialisability, then separately test recoverability, cascadelessness and strictness. Prerequisites are SQL modifications, basic graphs and transaction-local copies. A transaction is a logical read/write unit implementing a business activity, such as debiting A and crediting B together; a partial transfer violates the business invariant.

课程订货流程把客户资格、库存检查、库存扣减、订单和应收账款更新组合为一个工作单元。崩溃可能发生在任一SQL之间，因此BEGIN/COMMIT划定整体成功边界，ROLLBACK撤销未完成的效果。提交不代表每个数据页立刻落盘，持久性也可由已持久化日志与恢复过程保证，第12章会补全。

The course ordering process combines customer eligibility, stock checking, stock reduction, ordering and accounts-receivable updates into one unit. A crash can occur between SQL statements, so BEGIN/COMMIT define all-or-nothing success and ROLLBACK removes incomplete effects. Commit does not imply that every data page immediately reaches disk; durable logging plus recovery can provide durability, as Chapter 12 explains.

状态机中Active执行读写；最后一条操作后Partially committed仍可能因日志未持久化而失败；成功到Committed。出错转Failed，再回滚到Aborted/Terminated，按应用策略决定是否重启。不要把“执行完最后一条UPDATE”和“提交持久成功”当成同一个时刻。

In the state machine, Active performs reads and writes. After the final operation, Partially committed can still fail before durability is established; success reaches Committed. Errors move to Failed, followed by rollback to Aborted/Terminated and possible restart under application policy. Completing the last UPDATE is not the same moment as successful durable commit.

调度与本地计算：先画时间线Schedules and local computation: start with a timeline

来源 / Source: Lecture/Week10-TM(1).pdf · PDF p. 26-35（原资料留在本地版） · 本地逐页图文 / Local pages

调度（schedule/history）是多个事务操作的总顺序，但必须保留每个事务内部的程序顺序。记rᵢ(X)、wᵢ(X)、cᵢ、aᵢ为读、写、提交、回滚。read把数据库X复制到事务自己的局部变量；中间算术只改局部副本，直到write才改数据库。混淆这两个空间会算错丢失更新。

A schedule/history is a total order of operations from several transactions that preserves each transaction’s program order. Use rᵢ(X), wᵢ(X), cᵢ, aᵢ for read, write, commit and abort. A read copies database X into the transaction’s local variable. Arithmetic changes only that copy until a write updates the database. Mixing local and shared state leads to incorrect lost-update calculations.

Tutorial 10 Ex1初值y=20，T1加50、T2乘3。串行T1→T2给(20+50)×3=210；T2→T1给20×3+50=110。原交错两者先读20，T1本地算70、T2本地算60，先写70再写60，最终60。60既不是210也不是110，T1更新被T2旧副本覆盖。

Tutorial 10 Ex 1 starts y=20, with T1 adding 50 and T2 multiplying by three. Serial T1→T2 gives (20+50)×3=210, while T2→T1 gives 20×3+50=110. In the interleaving both read 20, compute local 70 and 60, then write 70 followed by 60. The final 60 equals neither serial result: T2’s stale local copy overwrites T1’s update.

四类并发异常的本质Four concurrency anomalies

丢失更新（lost update）是一个事务根据旧值写回，覆盖另一个已做的修改。脏读（dirty read/uncommitted dependency）是读到另一个尚未提交事务的写；若写者回滚，读者依赖了不存在的效果。不可重复读（unrepeatable read）是同一事务两次读同项，中间别的事务修改，使结果不同。

A lost update occurs when a transaction writes a stale value over another transaction’s modification. A dirty read, or uncommitted dependency, reads another transaction’s uncommitted write; if the writer aborts, the reader depended on a nonexistent effect. An unrepeatable read occurs when another transaction changes an item between two reads by the same transaction.

不正确汇总（incorrect summary）是在汇总多个项目时混合了不同时间的状态。例如X=500、Y=500，转账100保持总额1000；汇总先读旧X=500，转账后再读新Y=600，得到1100。它可能没有读到脏值，却仍不是一致快照。每个单独读值都“曾经正确”并不保证整组结果一致。

An incorrect summary combines states from different times. With X=500, Y=500, transferring 100 preserves a total of 1000. A summary that reads old X=500 and later new Y=600 reports 1100. It may avoid dirty values yet still lack a consistent snapshot. Each individual value having been correct at some time does not make the combined result consistent.

串行、可串行化与冲突等价Serial, serialisable and conflict-equivalent schedules

来源 / Source: Lecture/Week10-TM(1).pdf · PDF p. 44-56（原资料留在本地版） · 本地逐页图文 / Local pages

串行（serial）指一个事务做完再做下一个；n个不同事务有n!个串行排列。可串行化（serialisable）允许交错，但效果须与某个串行执行等价。不同串行顺序可以产生不同合法结果，如210与110；“正确”不是要求它们全部相同。一次具体初值恰好算出相同最终数值，也不证明对所有输入都等价。

Serial means completing one transaction before the next; n distinct transactions have n! serial orders. Serialisable permits interleaving whose effects are equivalent to some serial execution. Different serial orders can yield different valid results, such as 210 and 110; correctness does not require every serial order to agree. Coincidentally equal final values for one initial state do not prove equivalence for all inputs.

两操作冲突要同时满足：属于不同事务、访问同一数据项、至少一个是写。读读不冲突，同事务两操作不算跨事务冲突，不同数据项也不冲突。冲突等价（conflict equivalence）要求每一对冲突操作的相对顺序都一致；只比较最终值或无标签边集合不够。

Two operations conflict only if they belong to different transactions, access the same item and at least one writes. Read/read pairs, same-transaction pairs and different items do not form these inter transaction conflicts. Conflict equivalence requires the same relative order for every conflicting pair. Equal final values or identical unlabelled edge sets alone do not establish it.

优先图的构造、证明与拓扑序Precedence graphs, justification and topological order

优先图（precedence/serialisation graph）每个事务一个节点；若冲突操作中Ti的操作先于Tj，画Ti→Tj，并标记数据项与操作对。图无环当且仅当该调度冲突可串行化（conflict-serialisable）。理由是每条边约束串行先后，无环图有拓扑序满足全部约束；有环则要求某事务排在自己之前，无法满足。

A precedence/serialisation graph has one node per transaction. If Ti’s operation precedes Tj’s in a conflicting pair, add Ti→Tj and label the item and operation pair. A schedule is conflict-serialisable exactly when the graph is a cyclic. Every edge constrains serial order; an a cyclic graph has a topological order satisfying all constraints, while a cycle requires a transaction to precede itself.

例：r1(X),w1(X),r2(Y),w2(Y),c2,r1(Y),w1(Y),c1,r3(X),w3(X),c3。Y上T2写先于T1读写，得T2→T1；X上T1读写先于T3，得T1→T3。无环，唯一受约束顺序T2→T1→T3。若只有T1→T3和T2→T3，则T1与T2可交换，两个拓扑序都合法。

For r1(X), w1(X), r2(Y), w2(Y), c2, r1(Y), w1(Y), c1, r3(X), w3(X), c3, T2’s Y write precedes T1’s Y operations, giving T2→T1. T1’s X operations precede T3’s, giving T1→T3. The graph is a cyclic with order T2→T1→T3. If the only edges were T1→T3 and T2→T3, T1 and T2 could exchange places and both topological orders would work.

算法可逐数据项检查有序读写对，再做拓扑排序；朴素全配对O(m²)，图拓扑检测O(V+E)。一条边有多个冲突证据不影响是否有环。冲突可串行化是方便检验的充分类别，不等同所有可能的可串行化：第11章Thomas写规则会放过某些包含过时盲写的视图可串行化调度。

An algorithm can examine ordered read/write pairs per item and then topologically sort the graph. A naive all-pairs construction is O(m²), while graph detection is O(V+E). Multiple conflict witnesses on one edge do not change cyclicity. Conflict serialisability is a convenient sufficient class, not all possible serialisability: Thomas’s write rule in Chapter 11 can permit some view-serialisable histories with obsolete blind writes.

可恢复、无级联与严格性另行判断Test recoverability, cascadelessness and strictness separately

来源 / Source: Lecture/Week10-TM(1).pdf · PDF p. 36-42（原资料留在本地版） · 本地逐页图文 / Local pages

可恢复调度（recoverable schedule）：若Tj读到了Ti写的值，Tj提交必须晚于Ti提交。关键是读自（read-from）关系，要找该次read之前最近的有效write；不是同一数据项上所有曾写过的事务都自动成为依赖。若Ti回滚，仍依赖它的Tj不能再正常提交，需要回滚或重做。

A recoverable schedule requires that if Tj reads Ti’s written value, Tj commits only after Ti commits. Identify the read-from relation by the relevant most recent preceding write, rather than treating every historical writer of the item as a dependency. If Ti aborts, a Tj still dependent on it cannot simply commit normally; it must be rolled back or re computed.

无级联调度（cascadeless schedule）要求读别人的写之前，该写者已经提交；因此不会因读脏值而级联回滚。严格调度（strict schedule）更强：别人写了X但尚未提交或回滚时，其他事务既不能读X也不能写X。于是严格⊆无级联⊆可恢复。严格排除脏写，避免回滚旧值覆盖别人的新写。

A cascadeless schedule reads another transaction’s write only after that writer commits, avoiding cascading aborts from dirty reads. A strict schedule additionally forbids other transactions from writing the item until the writer commits or aborts. Thus strict⊆cascadeless⊆recoverable. Strictness excludes dirty writes, preventing rollback of an old value from overwriting another transaction’s new write.

但这条包含链不是可串行化的包含链。例如r1(X),r2(X),w1(X),c1,w2(X),c2没有读脏值或覆盖未完成写，是严格调度；两者仍先读旧值，可能丢失更新，冲突图有T1→T2与T2→T1。Strict 2PL协议能同时保证冲突可串行化和严格性，但“严格调度”这个性质单独不能替代冲突图检查。

This inclusion chain is not a serialisability chain. For example, r1(X), r2(X), w1(X), c1, w2(X), c2 neither reads dirty values nor overwrites an unfinished write, so it is strict. Both transactions still read the old value and can lose an update, with graph edges both ways. The Strict 2 PL protocol guarantees both conflict serialisability and strictness, but strictness alone does not replace a graph test.

Tutorial 10 Ex6(A)参考答案只把c2移到a1之后，却仍保留T2读到T1脏值再提交，这并未真正修复依赖。可选修复：把a1改成c1且放c2之前；若坚持T1回滚，则让T2在它回滚后重读重算或一起回滚。不要把“提交发生在写者终止之后”误当成“写者已经提交”。

In Tutorial 10 Ex 6(A), moving c2 after a1 while retaining T2’s dirty read does not genuinely repair the dependency. One repair changes a1 to c1 before c2. If T1 must abort, T2 must reread and re compute afterwards or also abort. Committing after a writer terminates is not the same as committing after that writer commits.

总结、英文论证与自测Summary, English reasoning and self-check

判断顺序：先检查事务内部顺序合法；再追踪值与异常；再逐对构造冲突图；另列read-from与commit/abort检查恢复性质。英文可写：“The edge T1→T2 is caused by w1(X) preceding r2(X). Since the graph is acyclic, the schedule is conflict-serialisable in the order …”。图有环时应精确说“not conflict-serialisable”，不要在没有进一步依据时排除更宽的等价类别。

Check program order first, trace values and anomalies, build conflicts pair by pair, then separately examine read-from and commit/abort order. A useful English justification is: “The edge T1→T2 is caused by w1(X) preceding r2(X). Since the graph is a cyclic, the schedule is conflict-serialisable in the order …”. With a cycle, state “not conflict-serialisable”; broader equivalence categories need further analysis.
