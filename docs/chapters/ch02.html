INFS7903 · CH02

SQL 查询思维与基础操作SQL reasoning and basic operations

学习目标与前置知识Learning objectives and prerequisites

来源 / Source: Lecture/Week01-Intro.pdf · PDF p. 38-46（原资料留在本地版） · 本地逐页图文 / Local pages

目标是把英语需求转换成可检查的 SQL：明确输出单位、关系路径、筛选层级、重复与 NULL 的含义。你应能独立完成 Prac1 的建表与数据操作，写相关子查询、聚合与“全部”条件。前置知识是键、外键与基本布尔逻辑。

The goal is to translate English requirements into verifiable SQL: identify the output unit, relationship paths, filtering level, duplicates and NULL semantics. You should complete Prac 1’s table and data operations independently, and write correlated sub queries, aggregation and universal conditions. Prerequisites are keys, foreign keys and basic Boolean logic.

先确定结果的一行代表什么Decide what one output row represents

解题第一步先写一句话：结果每行代表员工、部门，还是员工—项目组合？然后找标识它的键。连接子表常把一名员工扩成多行，如果最终只要员工名单，需用 EXISTS 或恰当 DISTINCT；不能看到重复就随手 DISTINCT，因为重复可能反映错误连接。

Begin with a sentence: does each output row represent an employee, a department or an employee–project pair? Identify its key. Joining a child table often expands one employee into several rows. For an employee list, use EXISTS or appropriate DISTINCT. Do not add DISTINCT reflexively: duplicates can reveal an incorrect join.

SQL 的概念求值顺序是 FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY。它帮助理解语义，并不规定实际物理执行顺序。WHERE 在分组前筛行，HAVING 在分组后筛组；SELECT 列表决定输出属性，ORDER BY 才保证输出顺序。

SQL’s conceptual evaluation order is FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY. This explains semantics without prescribing the physical execution order. WHERE filters rows before grouping; HAVING filters groups afterwards. The SELECT list defines output attributes, and ORDER BY establishes output order.

前置知识补充：NULL 表示缺失或未知，不是0也不是空字符串。x=NULL 得 UNKNOWN，必须用 IS NULL。WHERE 只保留TRUE，因此FALSE和UNKNOWN都被排除。COUNT(*)数行，COUNT(x)不数NULL，AVG(x)也忽略NULL；没有输入行时 SUM 通常为NULL，可以用COALESCE明确所需的零。

Prerequisite supplement: NULL represents missing or unknown information, rather than zero or an empty string. x=NULL evaluates to UNKNOWN; use IS NULL. WHERE retains only TRUE, excluding both FALSE and UNKNOWN. COUNT(*) counts rows, while COUNT(x) and AVG(x) ignore NULL. SUM over no rows normally returns NULL; use COALESCE when zero is required.

相关子查询与量词Correlated sub queries and quantifiers

非相关子查询不引用外层行，可以独立解释；相关子查询（correlated subquery）把外层当前行作为参数。例如查工资高于本部门平均工资的员工，内层按当前员工的Dno筛出同部门，再求AVG。课程称此类题“必须相关”，但等价的聚合连接或窗口方法也可表达；相关写法是清晰的一个选择。

An uncorrelated sub query does not refer to an outer row and can be understood independently. A correlated sub query uses the current outer row as a parameter. To find employees above their department average, filter the inner relation by that employee’s Dno before computing AVG. The lecture calls correlation necessary, but equivalent grouped joins or window methods can express the query too; correlation is one clear formulation.

SELECT e.SSN, e.FNAME, e.Dno
FROM EMPLOYEE e
WHERE e.Salary > (
  SELECT AVG(x.Salary) FROM EMPLOYEE x WHERE x.Dno=e.Dno
);

EXISTS 表示“至少一个匹配”，只关心是否有行；NOT EXISTS 表示“不存在反例”。NOT IN 遇到子查询中的NULL可能导致UNKNOWN，例如5 NOT IN (2,NULL)不能认定为真。以键匹配的 NOT EXISTS 通常更便于推理。先写存在什么，再决定是否否定，避免在英语的never、any、all之间混淆。

EXISTS means at least one matching row and only tests existence; NOT EXISTS means no counterexample exists. A NULL in a NOT IN sub query can produce UNKNOWN: 5 NOT IN (2, NULL) is not TRUE. A key-correlated NOT EXISTS is often easier to reason about. State what must exist before choosing negation, especially for English words such as never, any and all.

“做了所有项目”可转成“没有一个项目是他没做的”。对每个候选员工，外层寻找一个缺失项目；内层检查该员工与该项目的匹配。若找不到缺失项目就保留员工。项目集合为空时，所有员工都满足该条件，这是空集上的全称命题（vacuous truth）。

“Works on every project” becomes “there is no project that the employee does not work on.” For each candidate employee, search for a missing project; the inner query tests that employee–project pair. Keep employees with no missing project. If the project set is empty, every employee qualifies, illustrating vacuous truth for universal quantification.

SELECT e.*
FROM EMPLOYEE e
WHERE NOT EXISTS (
  SELECT 1 FROM PROJECT p
  WHERE NOT EXISTS (
    SELECT 1 FROM WORKS_ON w
    WHERE w.ESSN=e.SSN AND w.PNO=p.PNUMBER
  )
);

用数量代替集合包含关系必须非常小心。“会的语言和Eve一样多”不代表“至少会Eve的所有语言”。正确计数法要先限制到目标集合、按不同键计数，并处理空目标集合。例如Eve会英语和法语，另一个人会日语和德语，两个COUNT都为2但完全不满足包含。

Replacing containment with a count requires care. “Speaks as many languages as Eve” does not imply “speaks all Eve’s languages.” A valid count method must restrict to the target set, count distinct keys and handle an empty target. If Eve speaks English and French while another person speaks Japanese and German, both counts are two but containment fails.

完整例子：部门人数与高薪人数Worked example: department size and high earners

需求是“部门总人数超过5，列出其中工资大于40,000的人数”。一个6人部门只有1名高薪员工仍应出现；先WHERE salary>40000再HAVING COUNT(*)>5会把它删掉。先按全部员工分组，HAVING检验总人数，条件计数仅用于输出高薪人数即可，连0也能输出。

The requirement is to report the number earning above 40,000 in departments whose total head count exceeds five. A six-person department with one high earner must qualify. Filtering salary first and then applying HAVING COUNT(*)>5 incorrectly removes it. Group all employees, test total head count in HAVING and use conditional counting for the reported high-earner count, including zero.

SELECT Dno,
       COUNT(*) AS total_employees,
       COUNT(*) FILTER (WHERE Salary > 40000) AS high_earners
FROM EMPLOYEE
GROUP BY Dno
HAVING COUNT(*) > 5;

课程 Week01 p43 的子查询方法能选对部门，但外层WHERE删掉所有非高薪员工，所以没有高薪员工的合格部门不会输出一行0；页中“可能显示0”的说法与SQL不符。上面的条件聚合是为补齐这个边界而增加的教学解法。跨系统可用 SUM(CASE WHEN Salary>40000 THEN 1 ELSE 0 END)。

The sub query method on Week 01 p43 selects eligible departments, but its outer WHERE removes all non-high-earners, so an eligible department with no high earner does not produce a zero row. The slide’s suggestion otherwise conflicts with its SQL. The conditional aggregate above is an added teaching solution for that boundary. Across systems, use SUM(CASE WHEN Salary>40000 THEN 1 ELSE 0 END).

总结与自测Summary and self-check

SQL能力的核心是识别结果粒度和量词，再用键建立正确匹配。概念求值用于证明结果，执行计划用于理解性能。先保证含义正确，再研究第8–9章的优化；一个跑得快但漏掉0或空集合情况的查询仍然不正确。

SQL skill rests on output granularity, quantifiers and key-based matching. Conceptual evaluation proves results; execution plans explain performance. Establish correctness before optimising in Chapters 8–9: a fast query that mishandles zero counts or empty target sets is still incorrect.

C2-S1

自编练习：NOT IN 的子查询返回NULL时会怎样？

What happens to NOT IN when its sub query returns NULL?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

对没有匹配到明确值的候选项，比较可能为UNKNOWN，因此WHERE不保留它。用NOT EXISTS按实际相关键检查不存在匹配，可以避开这个全局NULL陷阱。仍需按业务决定候选键本身NULL是否应被保留。

A candidate not matching any definite value can yield UNKNOWN and be rejected by WHERE. Correlating NOT EXISTS on the intended key avoids this global NULL trap. Business semantics must still decide whether a NULL candidate key should qualify.

C2-S2

自编练习：为什么连接后的COUNT(*)可能多算员工？

Why can COUNT(*) after a join over count employees?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

一名员工可能匹配多条子记录。COUNT(*)数的是连接行而非独立员工；若需要员工数，用正确粒度预聚合、COUNT(DISTINCT eid)或EXISTS。不能在没有理解业务单位前机械去重。

One employee may match several child records. COUNT(*) counts joined rows rather than distinct employees. Pre-aggregate at the correct grain, use COUNT(DISTINCT eid), or use EXISTS when appropriate. Do not remove duplicates without understanding the business unit.
