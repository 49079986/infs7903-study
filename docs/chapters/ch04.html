INFS7903 · CH04

完整性约束、序列与触发器Constraints, sequences and triggers

学习目标与问题背景Learning objectives and motivation

来源 / Source: Lecture/Week04-Constraints-2026.pdf · PDF p. 3-14（原资料留在本地版） · 本地逐页图文 / Local pages

目标是把业务陈述改写成可检验的不变量，选对声明式约束或触发器，并能设计成功、失败及边界测试。前置是键、NULL、SQL数据修改与事务的基本概念。约束不只是报错机制：它把正确性的要求放在所有应用共享的数据库入口，避免某个程序忘记检查。

The goal is to turn business statements into testable in variants, choose declarative constraints or triggers, and design successful, failing and boundary tests. Prerequisites are keys, NULL, SQL modifications and the basic idea of a transaction. Constraints do more than raise errors: they place correctness requirements at a database boundary shared by applications, preventing one program from silently omitting a check.

静态约束（static constraint）描述一个状态是否合法，如结束日期晚于开始日期；动态约束（dynamic constraint）描述从旧状态到新状态是否允许，如工资不得降低。跨行的预算总和仍是状态性质，不因“涉及很多行”就自动变成动态约束。涉及旧值与新值比较时，触发器通常更自然。

A static constraint describes a valid state, such as an end date after a start date. A dynamic constraint describes a permitted transition, such as never reducing salary. A cross-row salary budget is still a state property; involving many rows does not automatically make it dynamic. A trigger is often natural when old and new values must be compared.

例如 CHECK(salary>=10000) 并不禁止NULL工资，因为比较为UNKNOWN。若业务要求人人工资至少10,000，需salary NUMERIC NOT NULL CHECK(salary>=10000)。同一行的多个列可一起比较，例如CHECK(end_date>start_date)，并非CHECK只能看一列。PostgreSQL CHECK不支持用子查询跨表计数；用函数偷偷跨表读取也不能提供可靠的持续一致性保证。

CHECK(salary>=10000) does not reject NULL salary because the comparison is UNKNOWN. If every employee must earn at least 10,000, use salary NUMERIC NOT NULL CHECK(salary>=10000). A CHECK can compare several columns in the same row, such as CHECK(end_date>start_date); it is not restricted to one column. PostgreSQL CHECK does not support sub queries for cross-table counting, and hiding such lookups in a function does not provide reliable ongoing consistency.

外键动作与依赖方向Foreign-key actions and dependency direction

外键从子行指向父键。插入子行时检查父是否存在；删除父时检查谁依赖它。RESTRICT/NO ACTION通常拒绝破坏引用的删除；CASCADE删除依赖行；SET NULL保留行但清空引用；SET DEFAULT填默认引用且默认值仍须合法。若外键列是复合主键的一部分，SET NULL会与非空要求冲突。选择动作要解释业务含义，而不是为了让DELETE“能跑”而全部CASCADE。

A foreign key points from a child row to a parent key. Inserting a child checks parent existence; deleting a parent checks dependants. RESTRICT/NO ACTION normally reject broken references; CASCADE removes dependent rows; SET NULL preserves rows without their reference; SET DEFAULT assigns a default reference that must still be valid. SET NULL conflicts with a foreign-key column that forms part of a primary key. Choose actions for business meaning rather than using CASCADE everywhere just to make DELETE succeed.

Prac2 删除ENGINEERING部门时，默认外键会阻止留下悬空员工。课程DIY要求改ON DELETE CASCADE，操作是先DROP CONSTRAINT fk_deptno，再以新动作ADD同名外键。效果是删除该部门同时删除其中员工。真实系统可能更适合拒绝或转移部门；本练习的选择来自题目，不是所有组织的通用策略。

In Prac 2, deleting ENGINEERING under the default foreign key must not leave orphaned employees. The DIY asks for ON DELETE CASCADE: drop fk_deptno, then add it again with the new action. Deleting the department then deletes its employees. A real organisation might prefer rejection or reassignment; cascading is this exercise’s requirement, not a universal policy.

Practical 2：用反例检验约束Practical 2: test constraints with counterexamples

来源 / Source: Practicals/Prac2-v2(1).pdf · PDF p. 3-9（原资料留在本地版） · 本地逐页图文 / Local pages

先完成Prac1后再建DEPT，依次添加主键、范围CHECK、名称UNIQUE与LOCATION非空；尝试删除并重加UNIQUE以学会按名称管理。前三条合法部门是10 Accounting Brisbane、20 Marketing Sydney、30 Engineering Gold Coast。后面20 Management重复主键、9 Finance超出两位数范围、70 Marketing重复名称，应分别失败。

Complete Prac 1 first, then create DEPT and add its primary key, range CHECK, name UNIQUE and mandatory LOCATION. Drop and re-add UNIQUE to practise named management. Valid departments are 10 Accounting Brisbane, 20 Marketing Sydney and 30 Engineering Gold Coast. The later rows 20 Management, 9 Finance and 70 Marketing respectively duplicate a key, violate the two-digit range and duplicate a name; test each failure separately.

原资料同时给出“六行多值INSERT”示意和“前三行成功”的预期。PostgreSQL一个INSERT语句中只要有一行失败，整个语句都失败，不会自动保留前三行。要得到课程预期，可先用一条语句插入三条合法行，再分开尝试三条非法行。若在显式事务中出现错误，应ROLLBACK或回滚到SAVEPOINT后继续，不能直接忽略错误。

The source shows a six-row multi-value INSERT sketch alongside the expectation that only the first three rows succeed. In PostgreSQL, one invalid row fails the entire INSERT statement; the first three are not automatically retained. Insert the three valid rows together, then test invalid rows in separate statements. If an explicit transaction enters an error state, ROLLBACK or roll back to a SAVE POINT before continuing.

EMP后续要求ENAME唯一、JOB非空、HIREDATE晚于2000-01-01，并建立部门外键。Prac1已经把HIREDATE转成DATE，因此应按DATE比较，Prac2表中的VARCHAR标注不能推翻实际DDL。插入部门40的David应因无对应父行而失败。检查约束可用\d emp；目录查询按约束名连接时还应考虑模式与表，避免不同表同名约束造成错配。

EMP then requires unique ENAME, non-null JOB, HIREDATE after 2000-01-01 and a department foreign key. Prac 1 already converted HIREDATE to DATE, so use date comparison; the VARCHAR label in Prac 2’s table does not override actual DDL. Inserting David with department 40 should fail without that parent. Inspect constraints with \d emp. Catalogue queries joining only by constraint name should also account for schema and table to avoid collisions.

触发器的事件、条件与动作Trigger events, conditions and actions

来源 / Source: Lecture/Week04-Constraints-2026.pdf · PDF p. 21-26（原资料留在本地版） · 本地逐页图文 / Local pages

触发器（trigger）按事件—条件—动作（event-condition-action，ECA）模型工作。事件如INSERT、UPDATE、DELETE；条件决定何时执行；动作检查或修改数据。BEFORE可验证或改NEW，AFTER适合在行修改后维护其他数据；INSTEAD OF在视图上替代原操作。FOR EACH ROW每影响一行触发一次，FOR EACH STATEMENT每条语句一次，即使影响0行也可能触发。

A trigger follows the event-condition-action (ECA) model. Events include INSERT, UPDATE and DELETE; conditions determine when the action applies; actions check or modify data. BEFORE can validate or change NEW, AFTER can maintain related data following a row change, and INSTEAD OF replaces an operation on a view. FOR EACH ROW fires once per affected row; FOR EACH STATEMENT fires once per statement, potentially even when zero rows are affected.

PostgreSQL触发器通常调用RETURNS trigger的函数。NEW是插入或更新后的行，OLD是更新前或删除的行；INSERT没有可用OLD，DELETE没有可用NEW。BEFORE行触发器RETURN NEW允许继续，RETURN NULL跳过该行；抛异常拒绝操作。AFTER行触发器返回值被忽略。不能在语句级触发器中把NEW当成唯一当前行，因为可能一次改了很多行。

A PostgreSQL trigger normally calls a function returning trigger. NEW is the proposed inserted or updated row; OLD is the pre-update or deleted row. INSERT has no usable OLD and DELETE no usable NEW. A BEFORE row trigger returns NEW to proceed, NULL to skip the row, or raises an exception to reject the operation. An AFTER row trigger’s return value is ignored. A statement trigger cannot treat NEW as one current row when a statement can change many rows.

CREATE OR REPLACE FUNCTION prevent_salary_reduction()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
 IF NEW.salary < OLD.salary THEN
   RAISE EXCEPTION 'Salary cannot be reduced';
 END IF;
 RETURN NEW;
END;
$$;
CREATE TRIGGER no_salary_reduction
BEFORE UPDATE OF salary ON person
FOR EACH ROW EXECUTE FUNCTION prevent_salary_reduction();

上述为教学改写，假设person.salary非空。10,000→9,000应拒绝，10,000→10,000允许，10,000→11,000允许。若允许NULL，必须先定义NULL转换的业务含义，再写IS DISTINCT FROM等条件。课程Oracle例子使用:NEW与BEGIN…END内联体，不能原样复制到PostgreSQL；Week04 p26还有INITCASP拼写，应核对INITCAP。通知经理的伪过程不等于真的拒绝更改。

The teaching rewrite assumes non-null person. salary. Reject 10,000→9,000, allow equality and allow 10,000→11,000. If NULL is allowed, first define its transition semantics and then use suitable tests such as IS DISTINCT FROM. The course Oracle examples use: NEW and an inline BEGIN…END body, which cannot be pasted unchanged into PostgreSQL. Week 04 p26 also has INITCASP where IN IT CAP should be checked. A pseudo procedure that notifies a manager does not itself reject an invalid change.

Practical 3：序列与触发器配合Practical 3: sequences and triggers

来源 / Source: Practicals/Prac3-V2.pdf · PDF p. 3-8（原资料留在本地版） · 本地逐页图文 / Local pages

序列（sequence）提供并发安全的数值分配对象，nextval每次取下一个值。它不是行数，也不保证没有间断：失败或回滚可能已经消耗号码。课程EMPNO_SEQ从1000开始，而已有EMP含1001–1004；如果直接沿用旧数据，第一个1000可能成功，后面的1001会冲突。要按实验前提清空练习数据或把起点调整到现有最大值以上，不能把“序列本身唯一”误认为“与已有表值永远不冲突”。

A sequence is an object for concurrency-safe numerical allocation, with nextval obtaining the next value. It is not a row count and does not guarantee gap less numbering: failed operations or rollbacks can consume values. The course EMPNO_SEQ starts at 1000 while existing EMP rows include 1001–1004. Reusing that data can let 1000 succeed and 1001 conflict. Follow the experiment’s reset assumptions or start above existing values; uniqueness within a sequence does not prevent collisions with pre-existing table values.

CREATE SEQUENCE deptno_seq MINVALUE 50 MAXVALUE 99
INCREMENT BY 10 START WITH 50;
CREATE OR REPLACE FUNCTION set_deptno() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
 NEW.deptno := nextval('deptno_seq');
 RETURN NEW;
END;
$$;
CREATE TRIGGER bi_dept BEFORE INSERT ON dept
FOR EACH ROW EXECUTE FUNCTION set_deptno();
INSERT INTO dept(dname,location) VALUES('Training','Brisbane');
SELECT * FROM information_schema.sequences;
SELECT tgname FROM pg_trigger WHERE NOT tgisinternal;

该部门序列依次给50、60、70、80、90，下一次100超过MAXVALUE=99会失败；这与两位数CHECK也一致。Prac3 p6把某次预期错误归因于CHECK，但若发生在EMP插入，重复主键、名称UNIQUE或外键也可能先报错。应以真实约束名和执行顺序诊断；本次未运行该实验，不能指定唯一真实错误。清理时先删使用它的触发器，再按依赖删除序列或函数。

The department sequence yields 50,60,70,80,90, then fails because 100 exceeds MAXVALUE=99; that also aligns with the two-digit CHECK. Prac 3 p6 attributes an expected error to a CHECK, but EMP insertions may first encounter duplicate keys, name uniqueness or foreign keys. Diagnose using the actual constraint name and execution order. This experiment was not run here, so no unique observed error is asserted. Clean up dependent triggers before removing their sequence or function as appropriate.

跨行规则、并发与完整测试Cross-row rules, concurrency and complete testing

“员工工资不超过经理工资”不能只检查插入员工：员工调薪、换经理，经理降薪都可能破坏不变量。需要覆盖所有能影响规则的事件。单次SELECT经理工资后检查也不自动防止另一个事务同时改经理工资；必须选择一致的锁定策略或更强隔离并处理重试。第11章将解释为什么“先查再写”可能竞争。

“Employee salary must not exceed the manager’s” requires more than checking employee insertion. Salary changes, manager reassignment and manager pay reductions can all break it. Cover every event affecting the invariant. Reading the manager’s salary and checking it does not automatically prevent another transaction changing that salary concurrently. Choose a consistent locking strategy or stronger isolation with retry handling; Chapter 11 explains this check-then-write race.

类似“部门工资总和小于预算”应说明严格小于还是小于等于、空部门总和按0处理、转部门影响旧部门和新部门、预算减少也要检查。触发器的形式正确不等于业务规则完整。测试矩阵至少包含正常值、等号边界、越界、NULL、批量语句、更新关键引用、删除和两个并发会话。

For “department total salary below budget”, specify strict versus inclusive comparison, treat an empty sum as zero when intended, account for both departments during transfers and check budget decreases too. A syntactically valid trigger need not implement the complete rule. Test normal values, equality boundaries, violations, NULL, multi row statements, changed references, deletions and two concurrent sessions.

延迟检查与历史验证Deferred checking and historical validation

来源 / Source: Lecture/Week04-Constraints-2026.pdf · PDF p. 27-32（原资料留在本地版） · 本地逐页图文 / Local pages

延迟（deferred）是把允许延迟的约束推迟到提交时检查，适合一个事务中暂时违反引用、最后修好的情形；禁用（disabled）是根本不检查；NOT VALID是暂不扫描验证旧数据，但约束仍检查新的相关修改。三者不可混同。PostgreSQL不是所有约束都能延迟，例如CHECK不按SET CONSTRAINTS延迟。

Deferred checking postpones a deferrable constraint until commit, useful when references are temporarily inconsistent within a transaction but repaired before it ends. Disabled means checking is turned off. NOT VALID skips initial validation of historical data while enforcing relevant new changes. These are distinct. PostgreSQL cannot defer every constraint; CHECK is not deferred by SET CONSTRAINTS.

ALTER TABLE emp ADD CONSTRAINT fk_dept_review
FOREIGN KEY(deptno) REFERENCES dept(deptno)
DEFERRABLE INITIALLY IMMEDIATE NOT VALID;
ALTER TABLE emp VALIDATE CONSTRAINT fk_dept_review;
BEGIN;
SET CONSTRAINTS fk_dept_review DEFERRED;
-- related modifications that restore the constraint by commit
COMMIT;

课程页中的ENABLE NOVALIDATE、DISABLE CONSTRAINT及ALTER TRIGGER … DISABLE主要是Oracle语法，不能因旁边链接写PostgreSQL就视为可执行。PostgreSQL触发器启停的典型语法为ALTER TABLE t DISABLE TRIGGER trigger_name，与约束延迟不是同一操作。操作类答案须写清DBMS与版本，课程服务器版本本次未知。

ENABLE NO VALIDATE, DISABLE CONSTRAINT and ALTER TRIGGER … DISABLE in the lecture are mainly Oracle syntax; a nearby PostgreSQL link does not make them executable there. PostgreSQL typically uses ALTER TABLE t DISABLE TRIGGER trigger_name for trigger control, which differs from deferring a constraint. State the DBMS and version for operational answers; the course-server version is unknown here.

总结与自测Summary and self-check

把约束设计成“规则—作用范围—受影响事件—并发策略—测试”的闭环。声明式机制优先处理键、域和引用，触发器处理转移或复杂跨行规则。每次例外都要说明NULL、历史数据和提交时状态。A1提供了年龄、容量、状态迁移和派生积分的综合应用，第13章建立对应索引。

Complete the loop from rule to scope, affected events, concurrency strategy and tests. Use declarative mechanisms for keys, domains and references, with triggers for transitions and complex cross-row rules. Explain NULL, historical data and commit-time state for exceptions. A1 combines age, capacity, state transitions and derived credits; Chapter 13 maps these applications.

C4-S1

自编练习：CHECK(x>0)是否拒绝NULL？怎样要求必填正值？

Does CHECK(x>0) reject NULL? How would you require a positive value?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

不会因该CHECK拒绝，NULL比较为UNKNOWN。使用x NUMERIC NOT NULL CHECK(x>0)，分别负责存在性与范围。测试NULL、0、负数与正数，前三类拒绝、正数通过。

The CHECK alone does not reject it because NULL comparison is UNKNOWN. Use x NUMERIC NOT NULL CHECK(x>0), separately enforcing presence and range. Test NULL, zero, negative and positive values: reject the first three categories and allow the last.

C4-S2

自编练习：为何两个看似正确的容量检查触发器仍可能超额报名？

Why can two correct-looking capacity triggers still overbook a shift?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

两个事务都可能读到同一个未满计数，各自允许一行后共同超过容量。触发器在各自事务内执行，不自带全局串行化。可围绕同一父资源行采用一致锁定并保证所有写路径遵守，或使用能检测冲突的隔离与重试设计。

Both transactions can read the same below-capacity count and independently allow an insertion whose combined effect exceeds capacity. A trigger executes within its transaction and does not provide global serialisation by itself. Consistently lock the shared parent resource across all write paths, or use conflict-detecting isolation with retries.
