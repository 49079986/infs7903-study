DIY完整教学示例与边界Complete teaching DIY examples and boundaries

经理工资示例假设emp(empno,mgr,sal)。BEFORE INSERT/UPDATE查经理，若自己有下属，自己的降薪也要检查。它适合单会话学习；并发时仍需一致锁定协议，且NULL经理表示无经理、NULL工资是否允许需先定义。MGR外键若存在，改EMPNO类型时必须同步；Prac原始MGR没有自引用外键，不应擅自假设已建。

The salary example assumes emp (empno, mgr, sal). BEFORE INSERT/UPDATE checks both the employee’s manager and subordinates when a manager changes pay. It is a single-session teaching example; concurrency needs a consistent locking protocol. Define NULL salary semantics and treat NULL manager as no manager. If a MGRFK exists, it must follow an EMPNO type change; the original practical does not create that self-FK.

CREATE FUNCTION check_employee_salary() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE manager_salary NUMERIC;
BEGIN
 IF NEW.mgr IS NOT NULL THEN
   SELECT sal INTO manager_salary FROM emp WHERE empno=NEW.mgr;
   IF NEW.sal>manager_salary THEN RAISE EXCEPTION 'Above manager salary'; END IF;
 END IF;
 IF EXISTS(SELECT 1 FROM emp e WHERE e.mgr=NEW.empno AND e.sal>NEW.sal)
 THEN RAISE EXCEPTION 'Below subordinate salary'; END IF;
 RETURN NEW;
END; $$;
CREATE TRIGGER trg_check_employee_salary BEFORE INSERT OR UPDATE ON emp
FOR EACH ROW EXECUTE FUNCTION check_employee_salary();

部门前缀编号示例在单独练习副本清空EMP后使用。假设前三字母在部门间唯一，DNAME稳定，MGR已改为文本以引用文本编号。计数表按部门原子递增，用RETURNING取本次号码，比SELECT MAX+1更能抵抗并发重复。本计数是事务内计数表，不是PostgreSQL独立SEQUENCE对象；若严格要求每部门sequence对象，则每部门建一个序列并用安全标识符引用，不能靠一个全局nextval表达每部门独立计数。

Use the prefix example after clearing EMP only in a separate practice copy. Assume department prefixes are unique, DNAME stable, and MGR converted to text for textual identifiers. Anatomic per-department counter with RETURNING avoids the SELECT MAX+1 race. This is a transactional counter table, not a standalone SEQUENCE object. If the task strictly requires separate sequence objects, create one per department and reference identifiers safely; one global next val does not provide per-department counts.

-- In an isolated practice copy / 仅在隔离练习副本
DELETE FROM emp;
DROP TRIGGER IF EXISTS bi_emp ON emp;
ALTER TABLE emp ALTER COLUMN empno TYPE VARCHAR(10) USING empno::text;
ALTER TABLE emp ALTER COLUMN mgr TYPE VARCHAR(10) USING mgr::text;
CREATE TABLE dept_emp_seq(deptno INTEGER PRIMARY KEY,n INTEGER NOT NULL);
CREATE FUNCTION prefixed_empno() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE prefix TEXT; number INTEGER;
BEGIN
 SELECT upper(left(dname,3)) INTO prefix FROM dept WHERE deptno=NEW.deptno;
 IF NOT FOUND THEN RAISE EXCEPTION 'Unknown department'; END IF;
 INSERT INTO dept_emp_seq VALUES(NEW.deptno,1)
 ON CONFLICT(deptno) DO UPDATE SET n=dept_emp_seq.n+1
 RETURNING n INTO number;
 NEW.empno:=prefix||number::text;
 RETURN NEW;
END; $$;
-- Remove the old numeric BI_EMP in the practice copy before attaching this one
CREATE TRIGGER bi_emp_prefix BEFORE INSERT ON emp
FOR EACH ROW EXECUTE FUNCTION prefixed_empno();

下面是严格使用SEQUENCE对象的替代版本，与上面的计数表版本二选一。先按上例在隔离副本清空EMP、将EMPNO/MGR转为文本，并移除旧bi_emp和bi_emp_prefix。准备时为每个已存在部门建立独立序列；新建部门之后也要建立对应序列。序列取号不会因事务回滚而归还，出现空号是预期行为。编号前缀唯一仍需另行保证。

The following alternative strictly uses SEQUENCE objects. Choose this or the counter-table version. First clear EMP in an isolated copy, convert EMPNO/MGR to text as above, and remove old bi_emp and bi_emp_prefix triggers. Preparation creates one independent sequence for each existing department; newly created departments also need a sequence. Sequence values are not returned after rollback, so gaps are expected. Prefix uniqueness remains a separate requirement.

-- Alternative in the same isolated practice copy; do not attach both generators
DROP TRIGGER IF EXISTS bi_emp ON emp;
DROP TRIGGER IF EXISTS bi_emp_prefix ON emp;
DO $$
DECLARE d RECORD;
BEGIN
 FOR d IN SELECT deptno FROM public.dept LOOP
   EXECUTE format('CREATE SEQUENCE IF NOT EXISTS public.%I START 1',
                  'emp_dept_'||d.deptno::text||'_seq');
 END LOOP;
END $$;
CREATE FUNCTION prefixed_empno_sequence() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE prefix TEXT; seqname REGCLASS; number BIGINT;
BEGIN
 SELECT upper(left(dname,3)) INTO prefix
 FROM public.dept WHERE deptno=NEW.deptno;
 IF NOT FOUND THEN RAISE EXCEPTION 'Unknown department'; END IF;
 seqname:=to_regclass(format('public.%I','emp_dept_'||NEW.deptno::text||'_seq'));
 IF seqname IS NULL THEN RAISE EXCEPTION 'Department sequence is missing'; END IF;
 number:=nextval(seqname);
 NEW.empno:=prefix||number::text;
 RETURN NEW;
END; $$;
CREATE TRIGGER bi_emp_prefix_sequence BEFORE INSERT ON public.emp
FOR EACH ROW EXECUTE FUNCTION prefixed_empno_sequence();

例如ENG与ACC对应不同DEPTNO，先后插ENG1、ACC1、ENG2。先查dname前三字母是否重名，再测试实际结果。上例假定public模式和已有部门名；在别的模式必须同步修改限定名。VARCHAR(10)限制前缀加数字的长度，因此不能声称无限可用。函数体只做静态审查，本次未在PostgreSQL运行。

For different department numbers with prefixes ENG and ACC, successive inserts yield ENG1, ACC1 and ENG2. Check for duplicate three-letter prefixes before testing.
