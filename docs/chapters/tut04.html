T04-E2-B

创建三个关系并声明适当主键、外键。

Write SQL to create the relations with appropriate primary and foreign keys.

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

课程提供答案；附教学推导、更正或明确假设 / Course answer with derivation, corrections or explicit assumptions

先Emp，再引用它的Dept，再Works。此解选择删除员工时清空部门经理、删除Works关联；删除部门时级联删除Works。课程SQL把ON DELETE前多写逗号，导致它脱离外键；这里放在对应REFERENCES之后。题目接受其他合理策略，但Ex2D必须与所选DDL一致。

Create Emp, then Dept, then Works. This solution clears a deleted manager reference and cascades deleted employee/department associations. The course syntax has commas separating ON DELETE from its FK; place the clause directly after the matching REFERENCES. Other justified policies are possible, but Ex 2 D must match the chosen DDL.

CREATE TABLE Emp(eid INTEGER PRIMARY KEY,ename TEXT,age INTEGER,salary NUMERIC);
CREATE TABLE Dept(did INTEGER PRIMARY KEY,dname TEXT,budget NUMERIC,
 managerid INTEGER REFERENCES Emp(eid) ON DELETE SET NULL);
CREATE TABLE Works(eid INTEGER REFERENCES Emp(eid) ON DELETE CASCADE,
 did INTEGER REFERENCES Dept(did) ON DELETE CASCADE,pcttime INTEGER,
 PRIMARY KEY(eid,did));

答案与推理 / Answer and reasoning

课程提供答案；附教学推导、更正或明确假设 / Course answer with derivation, corrections or explicit assumptions

题目未给还款公式，课程自行假设缺值时按15%。以下给明确的教学假设：还款始终等于周收入15%，salary等字段不相关；BEFORE中直接设置NEW避免AFTER再次UPDATE造成递归。若题意仅要求用户在同一语句显式提供两列，必须另定义检测规则，不能把15%伪装成题干事实。

The question gives no repayment formula; the course assumes 15% when missing. This teaching version explicitly assumes repayment always equals 15% of weekly income. Set NEW directly in BEFORE to avoid recursive AFTER updates. If the intended rule merely requires explicitly supplying both columns in a statement, specify a different detection rule; 15% is not a fact given by the question.

CREATE FUNCTION sync_repayment() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
 NEW.repay_amount := NEW.weekly_income*0.15;
 RETURN NEW;
END; $$;
CREATE TRIGGER sync_income BEFORE INSERT OR UPDATE OF weekly_income,repay_amount
ON person FOR EACH ROW EXECUTE FUNCTION sync_repayment();

取staff(id,dname,salary非空)与dept(name,budget非空)。每次人员插入、工资变动、调部门及部门预算变动，都需验证相关部门COALESCE(SUM,0)<budget；不满足就抛异常。课程语句级触发器却直接引用NEW.dname，且“通知”没有拒绝，不能直接执行。以下为单会话教学函数，按AFTER行触发；并发仍需所有写路径统一锁父部门并处理死锁/重试。严格小于在sum=budget时也必须拒绝。

Assume staff (id, dname, salary non-null) and dept (name, budget non-null). Validate COALESCE(SUM,0)<budget after insertions, salary changes, department transfers and budget changes, rejecting violations. The course statement trigger incorrectly uses row NEW.dname, and notification does not reject changes. This single-session teaching function uses AFTER row triggers; concurrent enforcement additionally needs consistent parent locking across all paths with deadlock/retry handling. Strict less-than also rejects equality.

CREATE FUNCTION check_budgets() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
 IF EXISTS (SELECT 1 FROM dept d WHERE
   COALESCE((SELECT SUM(s.salary) FROM staff s WHERE s.dname=d.name),0)>=d.budget)
 THEN RAISE EXCEPTION 'Department budget exceeded'; END IF;
 RETURN NULL;
END; $$;
CREATE TRIGGER check_staff_budget AFTER INSERT OR UPDATE OR DELETE ON staff
FOR EACH ROW EXECUTE FUNCTION check_budgets();
CREATE TRIGGER check_budget_change AFTER INSERT OR UPDATE ON dept
FOR EACH ROW EXECUTE FUNCTION check_budgets();

Define a table constraint on Dept ensuring all managers have age>30.

答案与推理 / Answer and reasoning

课程提供答案；附教学推导、更正或明确假设 / Course answer with derivation, corrections or explicit assumptions

课程给CHECK含子查询，不是PostgreSQL支持的CHECK。可用触发器：Dept新增/改managerid时查Emp.age，Emp改age时若它是经理也检查。以下假设age非NULL、允许无经理部门，只约束非空managerid；若要求人人有经理另加NOT NULL。年龄正好30拒绝，31允许。

The course CHECK with a sub query is not supported by PostgreSQL. Use triggers on Dept insert/manager changes and Emp age changes. This example assumes non-null employee age and allows departments without managers, constraining only existing manager references; add NOT NULL if managers are mandatory. Reject age 30 and allow 31.

CREATE FUNCTION managers_over_30() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
 IF EXISTS (SELECT 1 FROM Dept d JOIN Emp e ON e.eid=d.managerid
            WHERE e.age IS NULL OR e.age<=30)
 THEN RAISE EXCEPTION 'Manager must be older than 30'; END IF;
 RETURN NULL;
END; $$;
CREATE TRIGGER check_manager_assignment AFTER INSERT OR UPDATE ON Dept
FOR EACH ROW EXECUTE FUNCTION managers_over_30();
CREATE TRIGGER check_manager_age AFTER UPDATE OF age ON Emp
FOR EACH ROW EXECUTE FUNCTION managers_over_30();

T04-E4-3

删除工资高于其任一任职部门经理的员工信息，并保持引用完整性。

Delete all information about employees whose salaries exceed that of the manager of one or more departments they work in. Preserve relevant integrity constraints.

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

课程提供答案；附教学推导、更正或明确假设 / Course answer with derivation, corrections or explicit assumptions

先按W.eid=e.eid相关到当前员工，再对他工作的部门找到经理，存在一名较低薪经理则删除。选择Works.eid ON DELETE CASCADE、Dept.managerid ON DELETE SET NULL时，关联自动删除、经理引用清空。若采用Ex2C的经理非空要求，就需先重派经理或拒绝删除，不能同时假设SET NULL合法。课程首个查询缺W.eid=e.eid相关，且Work/Works混用；后面的ANY版修复相关意图。

Correlate W.eid=e.eid to the current employee, locate managers only for that employee’s departments and delete if any manager earns less. With Works.eid ON DELETE CASCADE and nullable Dept.managerid ON DELETE SET NULL, associations disappear and management references clear. If managers are mandatory as in Ex 2 C, reassign first or reject deletion. The course’s first query omits employee correlation and mixes Work/Works; its ANY version repairs the intended correlation.

DELETE FROM Emp e
WHERE EXISTS (
 SELECT 1 FROM Works w JOIN Dept d ON d.did=w.did
 JOIN Emp manager ON manager.eid=d.managerid
 WHERE w.eid=e.eid AND e.salary>manager.salary
);
