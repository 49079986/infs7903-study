INFS7903 · CH05

存储组织与磁盘计算Storage organisation and disk calculations

学习目标与前置知识Learning objectives and prerequisites

来源 / Source: Lecture/Week05-Storage.pdf · PDF p. 2-15（原资料留在本地版） · 本地逐页图文 / Local pages

目标是解释数据为何按块传输，区分随机与顺序I/O，计算容量、记录长度和块数，并依据工作负载选择heap、ordered或hash文件。前置知识补充：1 byte=8 bits；本教材容量计算默认十进制kB=1000 bytes、MB=10⁶ bytes，KiB=1024 bytes。不要在同一计算中混用毫秒和秒，也不要把位每秒当字节每秒。

The goal is to explain block transfers, distinguish random from sequential I/O, calculate capacities, record lengths and block counts, and select heap, ordered or hash files for a workload. Prerequisite supplement: one byte is eight bits; capacity calculations here use decimal k B=1000 bytes and MB=10⁶ bytes unless stated, while Ki B=1024 bytes. Do not mix milliseconds and seconds or bits/s with bytes/s.

存储层次（storage hierarchy）把正在使用的数据放RAM，大量持久数据放磁盘，归档可用更慢介质。RAM快但容量和成本受限且通常易失；HDD包含机械运动，SSD没有寻道臂与旋转等待。课程的寻道公式是HDD教学模型，不能直接用于估算SSD的机械延迟。缓存复用热点内容，缓冲协调速度不匹配；同一内存区在实现中可以兼具两种用途。

The storage hierarchy places active data in RAM, persistent bulk data on disk and archives on slower media. RAM is fast but limited, costly and normally volatile. HDD s involve mechanical motion; SSD s have no seek arm or rotational wait. The course’s seek formulas model HDD s and should not be applied as mechanical SSD delays. Caches reuse hot data and buffers smooth transfer-rate mismatches; an implementation can use a memory region for both purposes.

直接内存访问（direct memory access，DMA）由CPU设置源/目的地址、长度与方向，再让控制器完成大块传输，减少CPU逐字节搬运。I/O仍可能等待设备。排队延迟来自多个请求争设备，热点来自请求集中到同一区域，访问延迟来自设备完成单次请求所需时间。三个问题可能同时发生。

With direct memory access (DMA), the CPU sets addresses, length and transfer direction, then a controller moves a block without CPU copying each byte. The I/O can still wait for the device. Queueing delay comes from requests competing for service; hotspots concentrate requests on one area; access latency is the time to serve an individual request. All three can coexist.

磁盘几何与容量Disk geometry and capacity

来源 / Source: Lecture/Week05-Storage.pdf · PDF p. 16-24（原资料留在本地版） · 本地逐页图文 / Local pages

盘片（platter）有一个或两个记录表面；每面有同心磁道（track），每道划分扇区（sector）。所有表面相同半径的磁道合称柱面（cylinder）；磁头（head）随磁臂（arm）移动选择柱面，盘片旋转让目标扇区经过磁头。柱面数等于每表面磁道数，不是所有表面的磁道总数。

A platter has one or two recording surfaces, each with concentric tracks divided into sectors. Tracks of the same radius across surfaces form a cylinder. Heads move with an arm to select a cylinder; rotation brings the required sector under a head. The number of cylinders equals tracks per surface, not total tracks across all surfaces.

C_track = sectors_per_track × bytes_per_sector
C_cylinder = surfaces × C_track
C_disk = surfaces × tracks_per_surface × C_track

Tutorial 5 Ex7：B=512 bytes，每磁道20块，每面400道，15张双面盘片。表面数30；每道20×512=10,240 bytes；柱面400个；每柱面30×10,240=307,200 bytes；总盘30×400×10,240=122,880,000 bytes=122.88MB。这里每块512 bytes，题目把块与扇区容量取成一致；真实文件系统不必这样。

For Tutorial 5 Ex 7, B=512 bytes, there are 20 blocks per track, 400 tracks per surface and 15 double-sided platters. Thirty surfaces give 20×512=10,240 bytes per track, 400 cylinders, 30×10,240=307,200 bytes per cylinder and 30×400×10,240=122,880,000 bytes=122.88 MB overall. This exercise uses 512-byte blocks with the assumed sector-sized unit; real filesystems need not do so.

完整I/O计算：寻道、等待与传输Full I/O calculation: seek, wait and transfer

设转速r为rpm，一圈时间Trev=60,000/r毫秒；随机到达时平均旋转等待rd=Trev/2。传输率tr=每道容量/Trev，块传输时间btt=B/tr。单次随机块访问平均为s+rd+btt，其中s是平均寻道。连续k块若不再重新定位，成本近似s+rd+k×btt；k个随机块近似k×(s+rd+btt)。忽略排队、缓存、控制器等额外开销。

For rotation speed r rpm, a revolution takes Trev=60,000/r milliseconds, with average rotational delay rd=Trev/2 for random arrivals. Transfer rate tr=track capacity/Trev and block transfer time btt=B/tr. One random block averages s+rd+btt, where s is average seek time. If k contiguous blocks require no further positioning, approximate s+rd+k×btt; k random blocks cost k×(s+rd+btt). These models omit queueing, caching, controller and other overheads.

Trev=60000/r ms　　rd=Trev/2　　tr=C_track/Trev
T_random(k)=k(s+rd+btt)　　T_contiguous(k)=s+rd+k·btt

继续Ex7，r=3000rpm，所以Trev=20ms、rd=10ms。tr=10240/20=512 bytes/ms，btt=512/512=1ms。若s=30ms，一块41ms；20个随机块820ms，而20个连续块60ms。差异主要来自重复付出的寻道与等待，不是每块“字节突然传得更快”。

Continuing Ex 7, r=3000 rpm gives Trev=20 ms and rd=10 ms. tr=10240/20=512 bytes/ms and btt=512/512=1 ms. With s=30 ms, one block takes 41 ms, twenty random blocks 820 ms and twenty contiguous blocks 60 ms. The saving mainly avoids repeated seek and rotation costs; it does not make each byte transfer intrinsically faster.

Week05 pp22–24 的5400rpm例子约等于11.11ms/圈而非精确11ms。若保留精度，50×512=25,600bytes每道，tr=2,304,000 bytes/s，rd≈5.556ms；平均寻道10ms时读整道约26.667ms。课件26.5ms源于中间先取11ms。报告时注明舍入策略，避免把单位换算差异当概念错误。

The 5400 rpm example on Week 05 pp 22–24 is approximately 11.11 ms per revolution, not exactly 11 ms. Retaining precision with 50×512=25,600 bytes per track gives tr=2,304,000 bytes/s and rd≈5.556 ms. A10 ms seek plus a full-track read takes about 26.667 ms. The slide’s 26.5 ms rounds the revolution to 11 ms first. State rounding policy rather than confusing it with a conceptual difference.

记录布局与块因子Record layout and blocking factor

来源 / Source: Lecture/Week05-Storage.pdf · PDF p. 27-38（原资料留在本地版） · 本地逐页图文 / Local pages

文件（file）是记录的集合，物理上由块组成。块（block/page）是课程中的I/O单位，记录（record）是应用处理的业务单位。定长记录（fixed-length record）可用offset=记录号×R+字段偏移定位字段；例如SID4字节、Name24字节、Age4字节，Age偏移28，第二条记录Age偏移32+28=60。这里从0计数，不含页头。

A file contains records and is physically divided into blocks. A block/page is the course’s I/O unit; a record is the application’s business unit. For fixed-length records, field offset=record index×R+field offset. With SID=4 bytes, Name=24 and Age=4, Age begins at offset 28, and the second record’s Age at 32+28=60. This uses zero-based indexing and omits page headers.

定长布局简单，字段定位快，但最大长度字段会浪费空间，块尾也可能留下放不下整条记录的空隙。变长记录（variable-length record）可用长度前缀、分隔符或偏移目录记录边界；更节省实际值空间，却需要额外元数据，记录增长可能导致移动。课程顺序解析例子要先走过Name才能找Age；带偏移目录的实际布局可避免每次逐字段扫描。

Fixed layouts simplify operations and field access but can waste space inside maximum-length fields and at block tails. Variable-length records use length prefixes, delimiters or offset directories to mark boundaries. They save space for actual values but require metadata and can move when growing. The course’s sequential encoding requires traversing Name before Age; practical offset-directory layouts can avoid repeated field-by-field parsing.

不跨块（unspanned）要求一条记录整体装进一块：bfr=⌊B/R⌋，块数b=⌈N/bfr⌉。跨块（spanned）允许一条记录分布在多块；如果每块留P字节指针，按总字节估计b=⌈NR/(B−P)⌉。跨块与定长/变长是两个独立维度；课件“定长不能跨块”是其示例组织的约定，不是普遍物理定律。

Unspanned organisation keeps a whole record in one block: bfr=⌊B/R⌋ and b=⌈N/bfr⌉. Spanned organisation permits a record across blocks; if P bytes per block hold a pointer, estimate b=⌈NR/(B−P)⌉. Spanning and fixed versus variable length are separate dimensions. The slide’s statement that fixed-length records cannot span blocks is a convention of its example, not a universal physical law.

unspanned:　bfr=⌊B/R⌋,　b=⌈N/bfr⌉
spanned estimate:　b=⌈N·Ravg/(B−P)⌉

Ex8字段字节合计112，删除标记再1，R=113。512字节块只能放4条，20,000条需5,000块，每个装满4条的块余60字节。Ex9变长格式在每个出现字段上还加1字节类型：必现字段及两个标记100字节；选填部分=10×0.8+5×0.85+5×0.15+4×0.9=16.6，总平均116.6。虽然可选字段减少，类型开销可让平均记录反而大于113，不能先验认为变长一定更短。

In Ex 8, field bytes total 112 plus a deletion marker, giving R=113. A512-byte block holds four records, so 20,000 records need 5,000 blocks, leaving 60 bytes in each four-record block. In Ex 9, each present field also has a one-byte type tag: mandatory fields and two markers use 100 bytes; optional fields average 10×0.8+5×0.85+5×0.15+4×0.9=16.6, giving 116.6 bytes. Optional omission can be outweighed by tag overhead, so variable length is not automatically shorter.

三种文件组织与查询选择Three file organisations and workload choices

来源 / Source: Lecture/Week05-Storage.pdf · PDF p. 39-56（原资料留在本地版） · 本地逐页图文 / Local pages

堆文件（heap file）不按业务键排序，适合追加和全扫描。插入可读尾块、加记录、写回；删除常标记空位供复用。链表实现区分满块与有空闲块；目录实现记录每块剩余空间，便于找插入位置。heap不是内存管理中的堆，也不意味着每次查询能按值直接随机定位。

A heap file has no business-key order and suits appending and full scans. Insertion can read the last block, add a record and write it back; deletion can mark reusable space. Linked-list implementations separate full and non full blocks; directory implementations record free space to locate insertion pages. This heap differs from a memory-allocation heap and does not support direct value-based random lookup merely by being unordered.

有序文件（ordered/sequential file）按排序键物理存放，适合按该键二分定位或连续范围读取。插入要保序，可能移动很多记录，也可先写溢出区再定期合并。二分查找维护候选区间，每次取中点比较后删掉不可能的一半，保证目标若存在仍在剩余区间；文件没按查询字段排序时不能对该字段直接二分。

An ordered/sequential file physically follows a sort key, supporting binary positioning and contiguous range reads on that key. Insertions must preserve order and can move many records, or use an overflow area with periodic merging. Binary search maintains a candidate interval and discards the impossible half after each midpoint comparison, preserving any existing target in the remaining interval. It cannot be applied directly to an un sorted query field.

哈希文件（hash file）把记录放到h(k)指定的桶。课程例子把电话分机所有数字相加，再取末位：659072与652907之和都是29，落桶9。不同键落同桶叫碰撞；桶满后需溢出块。均匀散列降低链长，过高装载率或倾斜会让查找退化。范围内连续键不一定落相邻桶，因此范围查找通常需扫描文件。

A hash file places a record in bucket h (k). The course sums extension digits and takes the final digit: both 659072 and 652907 sum to 29 and map to bucket 9. Different keys mapping to one bucket collide; a full bucket requires overflow space. Uniform hashing reduces chains, while high load or skew can degrade search. Consecutive keys need not occupy adjacent buckets, so range queries normally scan the file.

表格是课程简单外存模型，M为数据块数，不包括缓存和索引。Hash的范围成本不能只数结果块，因为必须先发现在哪些桶。生命周期选择：先写入增长可用heap，稳定只读范围分析可用ordered，大量等值读写可考虑hash；如果读写条件不可预测，hash不自动胜出，还应结合第6章索引与更新成本。

The table uses the course’s simple external-memory model, with M data blocks and no cache or indexes. Hash range cost cannot count only output blocks because the system must first discover their buckets. During a lifecycle, append-heavy growth can suit heap, stable read-only range analysis ordered files, and equality-heavy reads/writes hashing. Unpredictable predicates do not automatically favour hashing; consider Chapter 6 indexes and update costs too.

总结与自测Summary and self-check

存储题先画层次：盘→面→道→块→记录，逐层核对单位。访问题先判断顺序还是随机，记录题先判断跨块与开销，文件题先问查询按哪个字段、等值还是范围。统计上成功唯一线性搜索约M/2块；失败搜索与需取全体匹配的非唯一搜索通常扫描全部。最坏二分探测次数更精确可写⌊log₂M⌋+1，课程常用⌈log₂M⌉近似，边界如M=1应单独处理。

For storage calculations, draw disk→surface→track→block→record and check units at every level. For access, distinguish sequential from random. For records, identify spanning and overheads. For files, ask which field and whether equality or range. A successful unique linear search averages about M/2 blocks; failed searches and complete non unique retrieval normally scan all. A more precise worst-case binary probe count is ⌊log₂M⌋+1; the course often approximates with ⌈log₂M⌉, so handle boundaries such as M=1 separately.

自编练习：每块1000字节、每条120字节且不跨块。81条需要多少块？

A block holds 1000 bytes and an unspanned record uses 120 bytes. How many blocks hold 81 records?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

bfr=⌊1000/120⌋=8。b=⌈81/8⌉=11。前10块各8条，末块1条；满块每块浪费40字节，末块空余880字节。不能把满块剩余量当成最后一块剩余量。

bfr=⌊1000/120⌋=8 and b=⌈81/8⌉=11. Ten blocks hold eight records each and the last holds one. A full block leaves 40 bytes, while the last leaves 880. Do not apply the full-block waste to the final partial block.

C5-S2

自编练习：为何减少记录字节数可能并未显著改善单条随机查询？

When would reducing bytes per record fail to improve a random single-record query much?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

如果仍需相同次数的随机定位，成本仍由寻道和旋转主导，传输节省只占小部分。但更短记录提高bfr、减少扫描页数、改善缓存，批量查询可能明显受益。必须说明所讨论的工作负载。

If the same number of random positions must be accessed, seek and rotation still dominate and transfer savings are small. Shorter records can nevertheless increase bfr, reduce scan pages and improve caching, substantially benefiting bulk queries. State the workload under discussion.
