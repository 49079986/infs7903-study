查询优化与执行计划Query optimisation and execution plans

对应 A2 专项：反连接与扫描计划 / Assignment connection →

学习目标与优化边界Learning objectives and optimisation boundaries

来源 / Source: Lecture/Week09-QPO-02.pdf · PDF p. 2-4（原资料留在本地版） · 本地逐页图文 / Local pages

目标是用合法等价规则改写查询树，计算选择率和结果估计，独立解释Prac6执行计划。前置是RA、连接方法与成本单位。基于规则（rule-based）利用启发式缩小计划空间，基于成本（cost-based）比较估计代价；实际系统可以结合两者。课件“多数DBMS偏好规则而非成本”的概括不宜直接推广到PostgreSQL，其规划使用成本与统计量。

The goal is to rewrite query trees legally, calculate selectivity and result estimates, and explain Prac 6 plans independently. Prerequisites are RA, join methods and cost units. Rule-based heuristics reduce the plan space, while cost-based planning compares estimated expense; systems can combine them. The lecture’s claim that most DBMSs favour rules over costs should not be generalised to PostgreSQL, whose planning uses statistics and costs.

选择率、不同值数与分布假设Selectivity, distinct values and distribution assumptions

来源 / Source: Lecture/Week09-QPO-02.pdf · PDF p. 5-13（原资料留在本地版） · 本地逐页图文 / Local pages

选择率（selectivity）S定义为满足条件的行数/总行数，范围[0,1]。S越小，过滤越强；口头说“highly selective”表示条件筛得少，不意味着比例S大。属性基数高通常使某个等值条件S较小，但有数据倾斜时不能只用NDV推断。统一用“选择率比例S”和“过滤能力强”能避免术语混乱。

Selectivity S is qualifying rows divided by total rows, within [0,1]. Smaller S means stronger filtering. The phrase highly selective means few matches, not a large numerical S. High NDV often implies a smaller equality fraction, but skew prevents inferring it from NDV alone. Distinguish the selectivity fraction S from filtering strength.

S = |σc(R)| / |R|　　estimated rows = |R|·S
uniform equality: S ≈ 1/NDV(A)
independent AND: S(P∧Q) ≈ S(P)S(Q)
independent OR: S(P∨Q) ≈ S(P)+S(Q)−S(P)S(Q)

假设50,000员工的200种爱好均匀分布，camping约250人；5,000部门在两层楼均匀，floor=1约2,500。若“露营爱好者”更集中在某楼，两个条件独立相乘就可能失真。直方图（histogram）记录值频率区间，常见值统计与多列统计能改善估计。估计错可让小表被当成大表或反之，导致计划选择失误。

With 50,000 employees and 200 uniformly distributed hobbies, camping matches about 250. With 5,000 departments evenly split over two floors, floor=1 matches about 2,500. If campers concentrate on one floor, independent multiplication can be wrong. Histograms describe frequency ranges, and common-value or multi column statistics improve estimates. Mis estimates can swap the apparent sizes of inputs and lead to poor plan choices.

投影与选择对低NDV的效果不同：选择一个低NDV值会保留较多行，但只投影该列并去重会得到很少行。例如100,000行CarOwner只有Yes/No，筛Yes约50,000行；投影CarOwner只有最多2行。不要因为都提到“选择性”而混用两个结论。

Selection and projection respond differently to low NDV. Selecting one low-NDV value retains many rows, whereas projecting that column with deduplication yields few. In 100,000 Car Owner rows with Yes/No, selecting Yes may retain 50,000 while projection yields at most two. Do not conflate the two conclusions because both mention selectivity.

四步查询树优化及其条件Four query-tree transformations and their conditions

来源 / Source: Lecture/Week09-QPO-02.pdf · PDF p. 14-23（原资料留在本地版） · 本地逐页图文 / Local pages

第一步建立规范表达式π输出(σ所有条件(R×S×T))，检查每个条件的来源。第二步把只涉及单个输入的选择下推，AND可拆、OR不可随意拆。第三步把跨表相等条件与乘积组合成连接，并选择较好的连接顺序。第四步下推投影，保留最终输出列及所有后续筛选、连接、分组需要的列。

First build the canonical expression πoutput (σall predicates (R×S×T)) and identify each predicate’s inputs. Second push single-input selections down; conjunctions split, disjunctions cannot be split arbitrarily. Third replace product-plus-join predicates with joins and select a useful join order. Fourth push projections down while retaining final output columns and everything needed by later filters, joins and grouping.

以Student、Enrolment、Course为例：先σGrade=7(Enrolment)，保留StID,CrsID；Course保留Code,Title；连接CrsID=Code后保留StID,Title；Student保留ID,Program；再连StID=ID，最后πTitle,Program。若第一步把StID删掉，无法找到专业；若把CrsID删掉，无法找到课程标题。

For Student, Enrolment, Course: first select Grade=7 from Enrolment, retaining St ID, Crs ID. Retain Code, Title from Course; join Crs ID=Code, then retain St ID, Title. Retain ID, Program from Student, join St ID=ID and finally project Title, Program. Dropping St ID early loses the programme link, and dropping Crs ID loses the course-title link.

CNF（conjunctive normal form）是AND连接若干OR组，DNF（disjunctive normal form）是OR连接若干AND组。例如(P∨Q)∧R等于(P∧R)∨(Q∧R)，这是分配律，不是直接由De Morgan单独完成。改写用于暴露可下推条件或可分支访问路径，但DNF展开可能使表达式指数增长。

CNF is an AND of OR groups; DNF is an OR of AND groups. For example, (P∨Q)∧R equals (P∧R)∨(Q∧R) by distributivity, not by De Morgan alone. Rewriting exposes push able predicates or alternative branch access paths, but full DNF expansion can grow exponentially.

“先做最小表”只是启发式。一个较大表若有极便宜索引、现成排序或强过滤，可产生更便宜计划；连接输出规模也由键与分布决定。对外连接，把右侧WHERE条件下推到ON可能改变是否保留左侧未匹配行。必须先证明等价，再比较成本。

“Use the smallest table first” is a heuristic. A larger input can be cheaper with a useful index, existing order or restrictive predicate, and join output depends on keys and distributions. For outer joins, moving a right-side WHERE predicate into ON can change retention of unmatched left rows. Prove equivalence before comparing cost.

Practical 6：逐项读懂执行计划Practical 6: reading an execution plan field by field

来源 / Source: Practicals/Prac6-V2.pdf · PDF p. 3-10（原资料留在本地版） · 本地逐页图文 / Local pages

前提是EMPLOYEE 50,000行、DEPARTMENT 1,009行，prep-6.sql本地未找到。课程先对deptno=30做EXPLAIN，显示Seq Scan与Filter；SET enable_seqscan TO off只是提高顺序扫描的估计惩罚，没有索引时仍可出现Seq Scan。再加主键P_DEPTNO自动产生唯一索引，用EXPLAIN ANALYZE观察Index Scan。下列流程根据资料整理，尚未连接课程服务器验证。

Prerequisites are 50,000 EMPLOYEE rows and 1,009 DEPARTMENT rows; prep-6.sql is absent locally. The course first EXPLAIN s deptno=30, producing Seq Scan and Filter. SET enable_seqscan TO off penal is es sequential scans; without an alternative index they can still appear. Adding primary key P_DEPTNO creates a unique index, then EXPLAIN ANALYZE shows an Index Scan. This source-based workflow was not verified against the course server.

EXPLAIN SELECT * FROM department WHERE deptno=30;
SET enable_seqscan TO off;
ALTER TABLE department ADD CONSTRAINT p_deptno PRIMARY KEY(deptno);
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM department WHERE deptno=30;
ANALYZE department;
SET enable_seqscan TO on;

计划中的cost=a..b表示输出首行前的启动成本和输出全部行的总成本；单位是规划器的相对成本，不是毫秒。rows是节点一次执行估计输出行数，width是估计平均字节宽度。actual time才是实测时间；loops是执行次数，某些actual行数和时间按每次循环平均显示。不能把父子total cost简单相加，因为父成本包含孩子工作。

cost=a.. b gives startup cost before the first row and total cost for all rows, in planner-relative units rather than milliseconds. rows estimates output rows per execution and width estimates average bytes. actual time is measured time; loops counts executions, with some actual counts and times shown as per-loop averages. Do not simply sum parent and child total costs because parents include child work.

Index Cond是能用于索引定位的条件，Filter是访问后再筛的条件。Index Only Scan说明所需列可从索引取得，但可能仍有Heap Fetches检查MVCC可见性；Prac6示例Heap Fetches=2，并不表示索引少了所需DEPTNO列。ANALYZE更新统计，VACUUM与可见性维护是相关但不同的工作。

Index Cond identifies conditions used for index navigation, while Filter applies after accessing candidates. Index Only Scan means required columns are available from the index, but Heap Fetches may still check MVCC visibility. Prac 6’s Heap Fetches=2 does not mean DEPTNO is missing from the index. ANALYZE updates statistics; VACUUM and visibility maintenance are related but different tasks.

Prac6的非等值连接E.deptno>D.deptno用Nested Loop，内侧索引按部门范围找匹配，Memoize按重复的e.deptno缓存查找结果。删除主键后索引消失，内侧Materialize缓存整个部门输入再反复比较，Rows Removed by Join Filter很大。Materialize计划节点是该次执行中的缓存，并不是永久CREATE MATERIALIZED VIEW。

Prac 6’s non-equality join E.deptno>D.deptno uses Nested Loop, with inner index range lookups and Memoize caching repeated e.deptno lookups. Dropping the primary key removes its index; an inner Materialize node then caches the department input for repeated comparisons, with many Rows Removed by Join Filter. This Materialize plan node is execution-time storage, not a persistent CREATE MATERIALIZED VIEW.

实验记录应写出数据状态、索引、统计更新、会话设置、完整计划、实际行数和时间；重复执行时缓存会变化。课程不同计划约421.529ms与3301.387ms是示例观测，不保证每台机器同样比例。enable_seqscan应在结束后恢复，避免把实验惩罚留给后续题。EXPLAIN不执行普通查询，EXPLAIN ANALYZE会实际执行，修改语句需特别注意其副作用。

Record data state, indexes, statistics, session settings, full plans, actual rows and timings; repeated runs can change cache state. The course’s approximately 421.529 ms versus 3301.387 ms is an example observation, not a guaranteed ratio on every machine. Restore enable_seqscan afterwards so later tasks do not inherit the penalty. EXPLAIN does not execute an ordinary query, while EXPLAIN ANALYZE executes its statement, including modification side effects.

总结与自测Summary and self-check

优化按“含义不变—估计规模—挑选实现—对照测量”推进。常见错误是把S大说成过滤强、删掉连接键、把cost当ms、见到Index Only就认定完全不读heap、或用一次耗时推断普遍性能。Tutorial 9把这些能力组合到Customer–Invoice–LineItem–Product查询中。

Optimisation proceeds through preserved semantics, estimated sizes, chosen implementation and measured comparison. Common mistakes are treating large S as strong filtering, dropping join keys, reading cost as milliseconds, assuming Index Only never touches the heap and generalising from one timing. Tutorial 9 combines these skills in the Customer–Invoice–LineItem–Product query.

A million-row table has NDV(type)=10 under uniformity. Estimate type=X; what if X occurs in 70% of rows?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

均匀估计S=0.1、100,000行；实际S=0.7、700,000行。仅知道NDV无法看出倾斜。可能从强过滤索引计划变为扫描更便宜；需统计量验证。

Uniformity gives S=0.1 and 100,000 rows; actual S=0.7 gives 700,000. NDV alone hides skew. The preferable plan can change from indexed access to a scan, requiring statistics to assess.
