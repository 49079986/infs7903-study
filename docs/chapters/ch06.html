索引与 B+ 树Indexes and B+ trees

对应 A2 专项：复合索引与域名索引 / Assignment connection →

学习目标与前置知识Learning objectives and prerequisites

学完本章，你应能从数据布局和查询条件选择索引，计算索引页数与访问次数，逐步画出 B+ 树插入和范围查询，并用执行计划检验索引是否真正被使用。前置知识是第5章的块、记录、取整与随机 I/O，以及第2章的查询条件。

After this chapter, you should be able to choose indexes from data layout and query predicates, calculate index pages and access counts, trace B+ tree insertion and range searches, and check actual index use in an execution plan. Prerequisites are blocks, records, rounding and random I/O from Chapter 5, and query predicates from Chapter 2.

索引解决的核心问题The problem an index solves

数据库索引（database index）是一条从搜索键（search key）到数据位置的访问路径（access path）。应用说“找 SSN=某值”，磁盘需要块地址；索引把两者连接起来。搜索键不一定唯一，也不一定是主键。例如姓氏可以作为搜索键，多个人可以同姓。

A database index is an access path from a search key to data locations. An application asks for a particular SSN, whereas the disk needs a block address; the index connects the two. A search key need not be unique or be a primary key. A surname can be a search key even when several people share it.

把索引想成按词排序的书后索引：先找词，再按页码取正文。数据库中的索引项通常包含键值和指针。索引记录比完整数据行短，同一页能放更多项，因此在索引中搜索往往比直接搜索数据文件更便宜。但找到索引项通常还要读数据页，计算时不能漏掉最后这一步。

Think of a book index: locate a sorted term, then use its page number to fetch the text. A database index entry normally contains a key value and a pointer. Entries are shorter than full records, so more fit on a page and searching the index is often cheaper than searching the data file. Finding an index entry usually still requires a data-page read; that final step belongs in the calculation.

索引也有代价。插入、删除或改变被索引列时，DBMS 必须维护索引；页可能分裂，日志也会增加。索引占用磁盘和缓存。它是否值得建立，取决于查询频率、过滤强度、写入频率与维护成本，而不是“列越多索引越好”。

Indexes also have costs. Inserting, deleting or changing indexed values requires maintenance, can split pages and generates additional logging. Indexes occupy disk and cache space. Their value depends on query frequency, filtering strength, write frequency and maintenance cost; adding more indexes is not an unconditional improvement.

物理顺序决定稀疏还是稠密Physical order determines sparse versus dense indexing

主索引

Primary index

按唯一排序键有序；通常每数据块一个锚点。

Ordered on a unique key; normally one anchor per data block.

稀疏；定位候选块，再在块内搜索。

Sparse; locate a candidate block, then search inside it.

聚簇索引

Clustering index

按非唯一字段分组有序；每不同值指向首块。

Ordered by a non unique field; one entry per distinct value points to its first block.

适合同值多行与连续读取；需要维护物理分组。

Useful for groups and contiguous reads; grouping requires maintenance.

辅助索引

Secondary index

文件未按该搜索字段排序；必须覆盖每行或每键的记录指针集合。

File not ordered on this field; cover every row or each key’s record-pointer list.

稠密；可在不同字段建立多个访问路径。

Dense; multiple fields can provide alternative access paths.

稀疏索引（sparse index）能省空间，是因为中间没有列出的键仍在可推断的连续区间中。例如锚点 10、40、70 分别指向三块，找键55时，选择40所在块。若数据任意分散，未列出的55可能在任何块，稀疏索引就无法保证找到它。稠密索引（dense index）必须保留足够的信息覆盖所有搜索值；非唯一键可以指向一串记录地址，而不必机械地重复存放同一个键。

A sparse index saves space because omitted keys remain in infer able contiguous intervals. If anchors 10, 40 and 70 point to three blocks, key 55 belongs in the block anchored by 40. With arbitrarily scattered records, 55 could be anywhere, so sparse entries cannot guarantee retrieval. A dense index retains enough information to cover all search values; a non unique key may point to a list of record addresses instead of repeatedly storing the same key.

注意课程术语与产品术语的差别：这里的“主索引”指有序文件上的稀疏结构，不能直接等同 PostgreSQL 的主键索引。PostgreSQL 的 PRIMARY KEY 自动建立唯一 B-tree 索引，却不会让 heap 文件从此永久按主键排序。索引定义等元数据存于系统目录，索引节点本身占用独立存储页。

Distinguish course terminology from product terminology. Here, a primary index means a sparse structure over an ordered file; it is not synonymous with a PostgreSQL primary-key index. PostgreSQL automatically creates a unique B-tree index for a PRIMARY KEY, but does not thereby keep the heap permanently sorted by that key. Index definitions and other metadata reside in the catalogue, while index nodes occupy their own storage pages.

从记录大小到多层访问成本From record size to multi level access cost

来源 / Source: tut/Tut06-Index-2026.pdf · PDF p. 1-5（原资料留在本地版） Ex1–2 · 本地逐页图文 / Local pages

先统一符号。B 是每块字节数，R 是每数据记录字节数，N 是数据记录数，V 是索引键字节数，P 是指针字节数。数据不跨块且忽略额外页头时，bfr=⌊B/R⌋，b=⌈N/bfr⌉。索引项大小 Rᵢ=V+P，索引块因子 f=⌊B/Rᵢ⌋。先向下取整得到容量，再向上取整得到所需块数。

First fix the notation. B is bytes per block, R bytes per data record, N data records, V bytes per index key and P bytes per pointer. For unspanned records and ignored page headers, bfr=⌊B/R⌋ and b=⌈N/bfr⌉. An index entry has size Rᵢ=V+P, giving index blocking factor f=⌊B/Rᵢ⌋. Round capacity down first, then round the required block count up.

bfr = ⌊B/R⌋　　b = ⌈N/bfr⌉　　Rᵢ = V + P　　f = ⌊B/Rᵢ⌋

Tutorial 6 Ex1 的 R=115，B=512，N=30,000，因此 bfr=4、b=7,500。SSN 与指针分别9和6字节，f=⌊512/15⌋=34。有序唯一键的主索引是7,500项，需⌈7500/34⌉=221块；无序文件上的辅助索引是30,000项，需⌈30000/34⌉=883块。同一个搜索键，物理布局不同，索引大小就不同。

In Tutorial 6 Ex 1, R=115, B=512 and N=30,000, giving bfr=4 and b=7,500. SSN and pointer sizes are 9 and 6 bytes, so f=⌊512/15⌋=34. A primary index on the ordered unique key has 7,500 entries and needs ⌈7500/34⌉=221 blocks. A secondary index over the unordered file has 30,000 entries and needs ⌈30000/34⌉=883 blocks. The same search key produces different index sizes under different physical layouts.

聚簇字段有1,000个不同值，每值30行。第一层索引1,000项占30块，第二层为30个下层块建30项，占1块，合计31个索引块、2层。每组30行按每块4行装，需要⌈30/4⌉=8块；查找并取全组的成本为2+8=10块。这里“每组在新块开始”使数据文件至少需要1,000×8=8,000块，不能再把最初的7,500块当成分组后的精确大小。

The clustering field has 1,000 distinct values and 30 rows per value. The first level has 1,000 entries in 30 blocks; the second indexes those 30 blocks and occupies one block, for 31 index blocks and two levels. Each group needs ⌈30/4⌉=8 data blocks, giving 2+8=10 reads to locate and retrieve a whole group. Because every group starts a new block, the grouped data file needs at least 1,000×8=8,000 blocks; the original 7,500 is not its exact post-clustering size.

对多层索引，最稳妥的方法是逐层取整：b₁=⌈Nᵢ/f⌉，b₂=⌈b₁/f⌉，一直到1。总空间是各层之和；路径访问只读每层一个块。不能把“总索引块数”误当成“一次搜索读取块数”。树高的对数估计还依赖扇出、占用率、根的特例及是否缓存根页。

For multi level indexes, round at each level: b₁=⌈Nᵢ/f⌉, b₂=⌈b₁/f⌉, continuing to one. Total space is the sum across levels, whereas a search reads one block per level. Do not confuse all index blocks with the blocks read by one search. Logarithmic height estimates also depend on fan out, occupancy, root exceptions and root-page caching.

Ex2 的课程答案是：辅助索引100块，二分查找⌈log₂100⌉=7次，再读数据块，共8次；B+ 树按半满有效容量50估计，⌈log₅₀10000⌉=3层，再读数据块，共4次。后者是题解的简化估计，不是给定字节数即可推出的严格最大高度定理：真实内部节点有 p 个树指针、p−1个键，叶还需记录指针与后继指针。作答时先说明沿用课程半满模型。

The course answer to Ex 2 gives 100 secondary-index blocks, ⌈log₂100⌉=7 binary-search reads and one data read, totalling eight. It estimates the B+ tree with effective half-full capacity 50, giving ⌈log₅₀10000⌉=3 levels plus one data read, totalling four. The latter is a simplified course estimate, not a strict maximum-height theorem determined by those byte sizes alone: internal nodes contain p child pointers and p−1 keys, while leaves need record and sibling pointers. State explicitly when using the course half-full model.

B+ 树：把定位与数据指针分开B+ trees separate navigation from data pointers

来源 / Source: Lecture/Week06-Indexing.pdf · PDF p. 30-45（原资料留在本地版） · 本地逐页图文 / Local pages

B+ 树（B+ tree）的内部节点保存分隔键和子节点指针，真正指向记录的指针集中在叶。所有叶深度相同，避免某个键落在特别长的路径中。叶之间有后继指针，范围查询只需定位起点，再顺着叶链扫描。B-tree 在内部节点也可能保存数据指针；B+ 树中命中内部键后仍须向下走到叶。

A B+ tree stores separator keys and child pointers in internal nodes, with record pointers concentrated in leaves. All leaves have equal depth, avoiding unusually long paths for some keys. Sibling pointers connect the leaves, so a range query locates its starting leaf and then follows the chain. A B-tree can also store data pointers internally; in a B+ tree, matching an internal key still requires descending to a leaf.

阶（order）p 在本课程指内部节点最多 p 个孩子，因此最多 p−1 个分隔键。不同教材对“阶”和叶容量的定义可能不同，必须先读题。本章 p=3 动画沿用课程插入图：叶最多2项；溢出3项时，左叶留2项、右叶1项；分隔键是左子树最大值，等于分隔键时走左边。Tutorial 6 Ex4–5 的另一组图采用右子树最小值作分隔键，等值走右边。两种约定都可正确，不能在同一棵树中混用。

In this course, order p means at most p children per internal node and therefore at most p−1 separators. Textbooks can define order and leaf capacity differently, so read the question’s convention first. The p=3 animation follows the course insertion figures: leaves hold at most two entries; three entries split into two on the left and one on the right; separators are left-subtree maxima, with equality going left. The other figures in Tutorial 6 Ex 4–5 use right-subtree minima, with equality going right. Either convention works, but a single tree must use one consistently.

插入先按搜索规则找到叶，保持键有序地加入。叶满时分裂，并把边界键复制到父节点，键仍留在叶。父节点若溢出，也分裂；内部分隔键的提升通常是移走，不是额外保留同一个内部项。根分裂创建新根，树高只在这时增加。插入成本通常与树高成正比，最坏会沿路径发生多次分裂。

Insertion descends to the correct leaf and inserts in sorted order. An overflowing leaf splits and copies its boundary key into the parent while retaining the key in a leaf. An overflowing parent also splits; promoting an internal separator normally removes it from the split internal node rather than retaining an extra internal copy. Splitting the root creates a new root, which is when height increases. Insertion cost is normally proportional to height, with splits potentially propagating along the path.

Deletion removes a key from its leaf. If occupancy drops below the stated minimum, first try redistribution with a sibling and update the parent separator; otherwise merge and remove a parent separator. Merging can propagate upwards, and a root with one remaining child can shrink the tree. 哈希、位图与组合条件Hashing, bitmaps and combined predicates

来源 / Source: Lecture/Week06-Indexing.pdf · PDF p. 23-29（原资料留在本地版） · 本地逐页图文 / Local pages

哈希索引（hash index）用 h(k) 找桶，适合等值查找，碰撞与溢出链会增加读取。它不保留键顺序，因此 k>某值不能沿相邻桶得到有序范围。位图索引（bitmap index）为每个不同值保留一条位向量，第 i 位表示第 i 行是否符合该值；多个条件可做位运算。低不同值数量、读多写少的分析场景较适合。

A hash index maps h (k) to a bucket and suits equality lookups, although collisions and overflow chains increase reads. It does not preserve key order, so adjacent buckets do not form an ordered range for k>some value. A bitmap index stores a bit vector for each distinct value, with bit i indicating whether row i has that value. Conditions combine through bit operations. Low-distinct-value analytical columns with few updates are suitable candidates.

dept=A: 111000　　mgr=QS: 101000　　chdr=N: 011101
AND → 001000 → 第3行 / row 3

上式对应课程位图例子：三个条件同时为1的只有第3行。不要把 PostgreSQL 执行计划里的 Bitmap Index Scan / Bitmap Heap Scan 等同于持久化的专用位图索引：它也可从普通索引动态构建记录位置位图。EMPNO 这种近乎每行不同的列若每值一条长位图，空间代价很大；B-tree 更自然。

In the course bitmap example, only row 3 has a one in all three vectors. A PostgreSQL Bitmap Index Scan or Bitmap Heap Scan is not the same as a dedicated persistent bitmap index: it can construct a bitmap of record locations dynamically from ordinary indexes. For EMPNO, where almost every row has a distinct value, a long bitmap per value is costly; a B-tree is a more natural choice.

Practical 5：从建立索引到解释证据Practical 5: from index creation to evidence

来源 / Source: Practicals/Prac05-v2.pdf · PDF p. 3-11（原资料留在本地版） · 本地逐页图文 / Local pages

前提是课程 prep-5.sql 已建立 EMP 100,000行与 PROJECT 200,000行；本地资料未包含该准备脚本，因此下列课程输出是原资料记录，本次没有在课程 PostgreSQL 实例重跑。先核对 \d emp、\d project 和行数，开启 \timing，运行 EXISTS 计数，建立 empno_idx，再运行同一查询。比较应同时查看结果、计划与多次耗时。课程计数180,000保持不变，48.228ms与47.200ms只说明该次测量差异很小。

The prerequisite is the course prep-5.sql data: 100,000 EMP rows and 200,000 PROJECT rows. That preparation script is absent locally, so the following outputs are records from the source, not reruns on the course PostgreSQL instance. Inspect \d emp, \d project and row counts, enable \timing, run the EXISTS count, create empno_idx, then repeat the same query. Compare results, plans and repeated timings. The course count remains 180,000; 48.228 ms versus 47.200 ms only shows a small difference in those measurements.

\timing on
SELECT COUNT(*) FROM PROJECT p
WHERE EXISTS (SELECT 1 FROM EMP e WHERE e.EMPNO = p.PROJECTLEADER);
CREATE INDEX empno_idx ON EMP(EMPNO);
EXPLAIN (ANALYZE, BUFFERS)
SELECT COUNT(*) FROM PROJECT p
WHERE EXISTS (SELECT 1 FROM EMP e WHERE e.EMPNO = p.PROJECTLEADER);
SELECT indexname, indexdef FROM pg_indexes WHERE tablename='emp';
CREATE EXTENSION IF NOT EXISTS pgstattuple;
SELECT tree_level, leaf_pages, index_size FROM pgstatindex('empno_idx');
\timing off

pgstatindex 的 tree_level=1 通常表示根在叶之上一层，根到叶需2个索引页，不能不看定义就当成“树只有1页”。扩展可能需要权限。删除普通索引用 DROP INDEX；约束依赖的索引需通过恰当的约束操作管理。Practical 随后删除 empno_idx、改变 EMPNO 类型并添加主键，以观察自动产生的唯一索引。操作会改变实验对象，应在练习副本中依次执行。

A pgstatindex tree_level of 1 normally means the root is one level above the leaves, giving two index pages on a root-to-leaf path; it does not mean the tree has only one page. The extension may require permission. Drop an ordinary index with DROP INDEX; manage a constraint-dependent index through the appropriate constraint operation. The practical then drops empno_idx, changes EMPNO’s type and adds a primary key to observe its automatic unique index. These operations change the experiment’s objects and belong in a practice copy, executed in sequence.

The function-index section requires the query and index to use the same expression. Indexing a column does not automatically index f (column). The course wraps TO_CHAR in an IMMUTABLE function: this asserts that identical inputs always give identical outputs, but does not magically make an environment-dependent function pure. Check locale, formatting and function behaviour. For a teaching supplement, lower (text) provides a clearer example with an appropriately immutable text operation.

C6-S1

自编练习：12,000行、每数据块6行、每索引块40项。比较稀疏主索引和稠密辅助索引的大小。

A file has 12,000 rows, 6 rows per data block and 40 index entries per block. Compare sparse-primary and dense-secondary index sizes.

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

数据块=12000/6=2000。主索引2000项，50块；辅助索引12000项，300块。若继续加多层，主索引50→2→1，共53块、3层；辅助索引300→8→1，共309块、3层。空间不同不必然导致高度不同。

Data blocks=12000/6=2000. The primary index has 2000 entries in 50 blocks; the secondary has 12000 entries in 300 blocks. Extending upwards gives 50→2→1, totalling 53 blocks and three levels for the primary; 300→8→1 gives 309 blocks and three levels for the secondary. Different storage sizes need not imply different heights.

C6-S2

自编练习：为什么返回全表90%记录的查询走索引可能更慢？

Why can a query returning 90% of a table be slower with an index?

先独立尝试：写出条件、方法和理由，再展开。 / Try first: write the conditions, method and reasons before revealing the solution.

答案与推理 / Answer and reasoning

自编练习 / Author-created exercise

需要遍历大量索引项，再访问几乎全部数据页；非聚簇情况下读取可能分散。顺序扫描一次读取全表可能更便宜。判断依据是匹配比例、物理局部性、缓存及计划测量，不能只看是否有索引。

It traverses many index entries and then touches almost all data pages, potentially with scattered reads for an unclustered index. One sequential scan can be cheaper. Assess the match fraction, physical locality, cache and measured plan rather than index existence alone.
